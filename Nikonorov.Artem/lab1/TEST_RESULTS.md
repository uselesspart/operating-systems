## 4. Проверки, выполненные с `sudo`

Пропущенный выше тест выполнен отдельно с правами root.

```bash
sudo ./tests/test_overflow_live.sh
```

Результат: **PASS**. Настоящее событие `IN_Q_OVERFLOW` получено от ядра, после переполнения монитор обнаружил новые каталоги и файлы, исходный лимит очереди (`16384`) восстановлен и проверен. С учётом этого прогона все 12 проверок набора имеют статус **PASS**.

Установка конфигурации rsyslog:

```bash
sudo ./scripts/install-rsyslog-config.sh
```

Результат: конфигурация установлена в `/etc/rsyslog.d/30-disk-monitor.conf`, проверена командой `rsyslogd -N1` и активирована; скрипт завершился сообщением `Installed, validated, and activated`. Перед этим `systemctl reload` вывел сообщение `Job type reload is not applicable for unit rsyslog.service`: у службы `rsyslog.service` в этой системе нет операции reload. Скрипт предусматривает этот случай (`systemctl reload rsyslog || systemctl restart rsyslog`) и активировал конфигурацию перезапуском

Повторный запуск теста маршрутизации после установки:

```bash
sudo ./tests/test_rsyslog.sh
```

Результат: **PASS**

Проект собирается командой `build.sh` без предупреждений. Все 12 проверок автоматического набора имеют статус PASS, включая live-переполнение очереди inotify (с `sudo`) и реальную маршрутизацию `LOG_LOCAL0` через rsyslog
