# Лабораторная работа по IPC, вариант 3

Игра "Волк и семеро козлят"

**Конфигурация:** родственные процессы, один к одному. Хост создаёт ровно один дочерний процесс с помощью `fork()`. Хост - волк и Qt GUI; дочерний процесс - козлёнок. Отдельный запуск клиента и handshake не используются.

Реализованы три механизма, на каждый собирается свой `host_*`:

- `host_mq` - POSIX-очереди сообщений (`mq_open`);
- `host_fifo` - именованные каналы (`mkfifo`);
- `host_sock` - `socketpair()`.

Для `mq` и `fifo` каждый процесс открывает свои дескрипторы уже после `fork()`.

## Синхронизация

До `fork()` хост создаёт общую область `mmap(MAP_SHARED | MAP_ANONYMOUS)` с двумя семафорами `sem_init(pshared = 1)`: `host_to_client` (клиент может читать) и `client_to_host` (хост может читать). Они задают строгую очерёдность чтения и записи.

Все ожидания (семафоры, чтение и запись каналов) ограничены 5 секундами. При превышении связь прерывается, клиент завершается.

## Архитектура

```text
src/
├── host.cpp                  # fork(), Qt-хост и обработка SIGINT/SIGTERM
├── client.cpp                # RunClient(): логика дочернего козлёнка
├── client.hpp
├── shared_sync.hpp/.cpp      # MAP_SHARED + sem_init, тайм-ауты и семафоры
├── game_engine.hpp/.cpp      # игровая логика
├── protocol.hpp              # формат IPC-сообщения
├── host_worker.hpp/.cpp      # блокирующий IPC в отдельном QThread
├── connection/
│   ├── conn.hpp              # общий интерфейс транспорта
│   ├── base_conn.cpp         # общая семафорная синхронизация Conn
│   ├── conn_mq.cpp           # POSIX message queues
│   ├── conn_fifo.cpp         # named pipes
│   └── conn_sock.cpp         # UNIX domain socketpair
└── gui/
    ├── host_window.hpp
    └── host_window.cpp       # Qt GUI и координация GameEngine

tests/
├── test_game_engine.cpp      # модульные тесты правил игры
└── test_connection.cpp       # fork, обмен и отмена ожидания для каждого транспорта
```

### Интерфейс `Conn`

Все транспорты реализуют один интерфейс `Conn`; конкретный класс выбирает `CreateConn()`. Конструктор принимает роль (`Host`/`Client`), PID хоста (для имён очередей и FIFO), указатель на общие семафоры и, для сокета, дескриптор из `socketpair()`. Общая семафорная логика вынесена в `base_conn.cpp`, каждый `conn_*.cpp` - один транспорт


## Требования

- Linux;
- C++17;
- CMake 3.16 или новее;
- GNU Make;
- Qt 6 Widgets.

На Ubuntu/Debian зависимости устанавливаются так:

```bash
sudo apt update
sudo apt install build-essential cmake qt6-base-dev
```

## Сборка

```bash
chmod +x build.sh
./build.sh
```

или:

```bash
make
```

`build.sh` собирает проект во временном каталоге, копирует исполняемые файлы в `bin/` и удаляет временный каталог, так что промежуточных файлов CMake в проекте не остаётся. Тесты выключены в обычной сборке и запускаются отдельно: `make test`.

## Запуск

Запустите 1 из вариантов:

```bash
./bin/host_mq
./bin/host_fifo
./bin/host_sock
```

Хост автоматически создаёт дочернего козлёнка. Второй терминал и передача PID не нужны. При закрытии окна, `Ctrl+C` или получении `SIGTERM` хост завершает дочерний процесс и удаляет созданные IPC-ресурсы. `SIGKILL` (`kill -9`) перехватить невозможно, поэтому для него гарантировать выполнение очистки нельзя.


## Правила игры

1. В каждом раунде волк вводит число 1-100 (кнопка или Enter); если за 3 с не введено, выбирается случайно.
2. Живой козлёнок бросает 1-100, мёртвый 1-50. Живой прячется, если расстояние до числа волка не больше `70/n`, иначе попадается. Мёртвый воскресает при расстоянии не больше `20/n`.
3. Для варианта 3 `n = 1`. Игра заканчивается, если козлёнок мёртв два раунда подряд.
4. GUI показывает числа волка и козлёнка и счётчики (спрятались, попались, воскресли, мёртвые).
