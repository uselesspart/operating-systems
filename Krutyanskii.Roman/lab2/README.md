# Lab 2 — IPC (вариант 1)

Сценарий 1 («Волк и козлята»). Конфигурация: **родственные, один к одному**.
Типы взаимодействия: **1 (mmap)**, **3 (shm)**, **5 (pipe)**. Знакомство — нет.
Синхронизация — **локальные семафоры** (`sem_init`, `pshared=1`) в разделяемой памяти.

## Структура
- `src/conn_mmap.cpp`, `src/conn_shm.cpp`, `src/conn_pipe.cpp` — типы взаимодействия,
  каждый в своём классе с одинаковым интерфейсом `Conn` (`Read`/`Write`).
- `src/host.cpp` — хост (Qt GUI). Тип соединения выбирается на этапе компиляции
  макросом `TYPE_*`, поэтому каждый `host_<type>` использует только своё соединение.
- `src/client.cpp` — заглушка. В родственной конфигурации клиент — это процесс,
  порождённый `fork` внутри хоста, отдельный исполняемый файл не используется.
- `CMakeLists.txt` — автоматически находит `src/conn_*.cpp` и для каждого строит
  `host_<type>` и `client_<type>`. Добавление нового типа не требует правки CMake.

## Сборка (WSL)
```bash
sudo apt update
sudo apt install -y build-essential cmake qtbase5-dev
bash build.sh
```
`build.sh` сам создаёт и очищает каталог `build/`, поэтому промежуточные файлы
(в т.ч. `*.o`) не появляются в корне проекта.

Запуск (нужен дисплей; в WSL — WSLg либо `xvfb-run`):
```bash
./build/host_mmap
./build/host_shm
./build/host_pipe
```

## Проверка без Qt
Синтаксическая проверка не создаёт объектных файлов:
```bash
g++ -std=c++17 -Wall -Werror -Isrc -fsyntax-only src/conn_mmap.cpp src/conn_shm.cpp src/conn_pipe.cpp
```

## Правила игры (n = 1 козлёнок)
- Хост (волк) загадывает число 1..100. Если за 3 с в GUI не ввести число — берётся случайное.
- Живой козлёнок бросает 1..100, мёртвый — 1..50.
- Если |волк − козлёнок| ≤ 70/n — козлёнок спрятался (жив); иначе его поймали (мёртв).
- Если мёртвый козлёнок дал |волк − козлёнок| ≤ 20/n — он воскресает.
- Игра заканчивается, когда все козлята мертвы 2 хода подряд.
- Любое ожидание семафора имеет тайм-аут 5 с; по тайм-ауту связь прерывается,
  клиент останавливается, в GUI выводится сообщение.
