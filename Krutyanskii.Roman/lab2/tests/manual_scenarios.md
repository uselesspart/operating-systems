# Ручная проверка лаб. 2 (в WSL)

## Сценарий 1 — обычная работа
```bash
bash build.sh
./build/host_mmap        # нужен дисплей (WSLg или xvfb-run ./build/host_mmap)
```
Ожидаем: окно Qt, статус меняется по раундам и показывает числа волка/козлёнка
и число спрятавшихся/попавшихся/мёртвых, в терминале строки `[LOG] Host rN wolf=...
kid=...` и `[LOG] Kid sent ...`. Сообщения `Timeout - kid is not responding` быть
не должно. Игра завершается после 2 ходов подряд со мёртвым козлёнком
(`[LOG] Kid finished`, `GAME OVER`).

`host_shm` и `host_pipe` проверяются так же и ведут себя идентично.

## Сценарий 2 — тайм-аут
Убить процесс козлёнка неудобно (он ребёнок хоста), поэтому тайм-аут проверяется
просто тем, что при штатной работе он не возникает. Код ожидания:
`semWait(..., 5000)` — при превышении печатается статус и клиент останавливается.

## Сценарий 3 — автотесты (unit + интеграционные)
```bash
bash build.sh            # нужны собранные host_*
bash tests/run_tests.sh
```
`run_tests.sh` собирает `tests/unit_tests.cpp` в `build/unit_tests_bin`, прогоняет
unit-тесты и затем headless-проверку всех `host_<type>` (нужен дисплей; без
`DISPLAY` интеграционная часть сама пропускается).

Ожидаем unit: PASS для mmap/shm/pipe, полиморфизма, очистки `/dev/shm`,
underflow-тайм-аута pipe, тайм-аута семафора и локального семафора через `fork`.
Интеграционные: для каждого `host_<type>` ≥ 2 раунда и ни одного `timeout`.

## Сценарий 4 — очистка /dev/shm
```bash
./build/host_shm &        # после завершения host_shm файл lab2_shm удаляется
```

## Сценарий 5 — строгая сборка без объектных файлов
```bash
g++ -std=c++17 -Wall -Werror -Isrc -fsyntax-only \
    src/conn_mmap.cpp src/conn_shm.cpp src/conn_pipe.cpp
```
`-fsyntax-only` ничего не пишет на диск, поэтому `*.o` в корне не появляются.
