# Лабораторная работа №1. Демон Linux (вариант 14)

Демон периодически проверяет каталоги, указанные в конфигурационном файле. Если в каталоге `folder` отсутствует защитный файл `ignfile`, демон удаляет всё содержимое каталога, включая вложенные файлы и папки. Сам каталог сохраняется.

Если защитный файл присутствует, очистка не выполняется.

События запуска, очистки, изменения конфигурации, ошибки и завершение работы записываются в системный журнал через `syslog`.

**Язык:** C++17. **ОС:** Linux.

## Сборка

```bash
./build.sh
```

Скрипт использует `g++` с параметрами `-std=c++17 -Wall -Werror`. Промежуточные файлы удаляются, результат сборки — `./daemon_lab1`.

## Конфигурация

Файл конфигурации состоит из правил вида:

```text
interval 20
/tmp/lab1_demo/trash keep.me
```

- `interval N` — интервал проверки в секундах (от 1 до 86400). По умолчанию — 20 секунд.
- `folder ignfile` — путь к каталогу и имя защитного файла. Путь может быть абсолютным или относительным к расположению конфигурационного файла.

Поддерживается произвольное количество правил для разных каталогов. Первая проверка выполняется сразу после запуска демона.

Пример конфигурации находится в `config/example.conf`.

**Внимание:** при отсутствии `ignfile` содержимое каталога действительно удаляется. Используйте только специально подготовленные тестовые каталоги.

## Запуск и управление

Перед первым запуском создайте тестовый каталог и защитный файл:

```bash
mkdir -p /tmp/lab1_demo/trash
touch /tmp/lab1_demo/trash/keep.me
```

Запуск демона:

```bash
./daemon_lab1 --pid-file /tmp/lab1_demo/daemon.pid config/example.conf
```

Управление сигналами:

```bash
kill -HUP "$(cat /tmp/lab1_demo/daemon.pid)"
kill -TERM "$(cat /tmp/lab1_demo/daemon.pid)"
```

`SIGHUP` — перечитывание конфигурации без перезапуска. При ошибках новая конфигурация отклоняется, предыдущие настройки сохраняются.

`SIGTERM` — корректное завершение с записью в журнал и удалением PID-файла.

Повторный запуск с тем же PID-файлом определяет предыдущий экземпляр, проверяет его через `/proc` и файловые блокировки, отправляет `SIGTERM` и ожидает завершения до 5 секунд.

Путь к конфигурации преобразуется в абсолютный до демонизации. PID нового экземпляра записывается после `fork`.

Дополнительно поддерживается режим `--foreground` для запуска без перехода в фоновый режим.

Просмотр журнала:

```bash
journalctl -t daemon_lab1 --no-pager
```

## Устройство программы

Класс `Daemon` реализован по паттерну Singleton.

| Модуль | Назначение |
|---|---|
| `Config` | Чтение и проверка конфигурационного файла |
| `SafeCleaner` | Проверка защитного файла и очистка каталогов |
| `PidFile` | PID-файл, блокировки, проверка и остановка предыдущего процесса |
| `Logger` | Запись событий в системный журнал |
| `Daemon` | Демонизация, сигналы, периодическая работа и управление компонентами |
| `main.cpp` | Обработка аргументов и запуск демона |

Для демонизации используются `fork`, `setsid`, `chdir("/")`, закрытие файловых дескрипторов и перенаправление стандартных потоков в `/dev/null`.

Сигналы обрабатываются через `sigtimedwait`. Очистка выполняется с проверкой защищённых путей и без рекурсивного перехода по символическим ссылкам.

## Тестирование

Запуск всех тестов:

```bash
./tests/run_tests.sh
```

В каталоге `tests/` находятся модульные тесты `Config`, `SafeCleaner`, `PidFile` и `Daemon`.

В `tests/integration/` расположены пять интеграционных тестов: проверка демонизации и очистки, PID-файла, безопасности каталогов, `SIGHUP` и `SIGTERM`.

Тесты запускаются без `sudo`. Для проверки очистки используются временные каталоги.
