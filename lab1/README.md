# Лабораторная работа 1. Демон Dir cleaner (вариант 7)

Демон периодически, через заданный интервал, проверяет папку 1 из конфигурационного файла и
**удаляет все её подпапки** (вместе с содержимым). Обычные файлы в папке 1 и сама папка остаются.
Вторая папка (необязательная) читается из конфига, но по условию варианта не изменяется.
Запуск, ошибки, перечитывание конфига, очистки и завершение работы записываются в syslog
(`openlog`/`syslog`/`closelog`). Только Linux: используются `fork`, `/proc`, `sigtimedwait`.

## Сборка

```bash
./build.sh            # результат: ./daemon, промежуточные файлы удаляются
```

Сборка идёт напрямую через `g++ -std=c++17 -Wall -Werror`.

## Тесты

```bash
./run_tests.sh                 # все тесты
./run_tests.sh -L unit         # только unit-тесты
./run_tests.sh -L component    # только компонентные
./run_tests.sh -R Sighup       # по имени
```

Нужны `g++`, `cmake`, `libgtest-dev`.

| Каталог | Что проверяет |
|---|---|
| `tests/ut/` | классы по отдельности: разбор конфига, удаление подпапок, pid-файл и `/proc`, синглтон демона |
| `tests/ct/` | настоящий демон: демонизация, действие над папками, сигналы, pid-файл, повторный запуск, сообщения в syslog |

Компонентные тесты подменяют `/dev/log` своим сокетом и читают, что демон пишет в журнал.
Сокет создаётся только если `/dev/log` не существует (чтобы не ломать журнал хоста), поэтому
два теста про syslog надёжно выполняются в чистом Docker-контейнере от root, а на обычном
Linux с journald они пропускаются (`SKIP`).

## Конфигурация

Файл `daemon.conf` в рабочей папке (или путь первым аргументом):

```
interval 20
dir1 /tmp/test_a
dir2 /tmp/test_b      # необязательно, не изменяется
```

- `interval N` — период между проверками в секундах (целое > 0);
- `dir1 путь` — папка, из которой удаляются все подпапки;
- `dir2 путь` — вторая папка (необязательно);
- пути абсолютные или относительные папке, где лежит конфиг; могут содержать пробелы;
- `#` начинает комментарий, пустые строки игнорируются.

Абсолютный путь к конфигу запоминается при запуске (до смены рабочей директории на `/`),
поэтому перечитывание по `SIGHUP` работает независимо от того, откуда был запущен демон.
Если новый конфиг некорректен, демон пишет ошибку в syslog и продолжает работать со старыми
настройками.

Быстрая проверка: `./demo.sh` — скрипт создаёт `/tmp/test_a` и `/tmp/test_b` с тестовыми
файлами и подпапками, запускает демон и показывает, что осталось в папках.

Демон работает в Linux. На Mac собирайте и запускайте его внутри контейнера
(Docker Desktop должен быть запущен):

```bash
docker run -it --rm -v "$PWD":/app -w /app ubuntu:24.04 bash
apt-get update && apt-get install -y g++ make cmake libgtest-dev
./build.sh && ./demo.sh
./run_tests.sh
```

## Запуск и управление

```bash
./daemon                                      # конфиг ./daemon.conf
./daemon /путь/к/daemon.conf                  # или явный путь
kill -HUP  $(cat /tmp/dirclean_daemon.pid)    # перечитать конфиг
kill -TERM $(cat /tmp/dirclean_daemon.pid)    # завершить
```

Просмотр журнала:

```bash
journalctl -t dirclean_daemon -f       # journald
grep dirclean_daemon /var/log/syslog   # если используется rsyslog
```

Повторный запуск находит старый экземпляр по pid-файлу `/tmp/dirclean_daemon.pid`, проверяет
его наличие через `/proc/<pid>`, отправляет ему `SIGTERM`, дожидается завершения (до 5 секунд)
и после демонизации записывает свой pid. Путь к pid-файлу можно переопределить переменной
окружения `DIRCLEAN_PID_FILE` (её используют тесты).

## Устройство

Класс `Daemon` — синглтон (доступ через `Daemon::instance()`, конструктор приватный,
копирование запрещено).

| Модуль | Назначение |
|---|---|
| `src/config` | разбор конфига, приведение относительных путей к абсолютным |
| `src/cleaner` | удаление всех подпапок папки 1 (символические ссылки не разыменовываются) |
| `src/pid_manager` | pid-файл, проверка процесса через `/proc`, остановка старого экземпляра |
| `src/daemon` | синглтон демона: `fork` ×2, `setsid`, `chdir("/")`, закрытие дескрипторов, сигналы, главный цикл |
| `src/main.cpp` | точка входа |

Главный цикл ждёт сигналы через `sigtimedwait` с таймаутом до следующей проверки: `SIGTERM`
пишет сообщение в журнал, удаляет pid-файл и завершает работу, `SIGHUP` перечитывает конфиг и
сразу выполняет проверку. Первая проверка выполняется сразу после запуска, затем каждые
`interval` секунд.
