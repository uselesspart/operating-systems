# Лабораторная работа №2. «Волк и семеро козлят» (вариант 8)

Сценарий 1, конфигурация **«Родственные. Один ко многим»**, типы взаимодействия:
**5 — программные каналы (`pipe`)**, **6 — именованные каналы (`fifo`)**, **7 — сокеты (`sock`)**.

Хост — волк, приложение с графическим интерфейсом на Qt. Клиенты — козлята, процессы-потомки
хоста: хост создаёт их через `fork`. Отдельной программы-клиента нет; `client_*` не собираются.
Козлёнок знает свой номер из `fork`, знакомство через сигналы не используется.

На каждом ходу волк бросает число 1..100 (пользователь вводит его в окне; если за 3 с не ввёл —
число случайное), живые козлята бросают 1..100, мёртвые — 1..50, n — число козлят:

- живой спрятался, если |козлёнок − волк| ≤ 70/n, иначе попался и умер;
- мёртвый воскрес, если |козлёнок − волк| ≤ 20/n;
- до появления козлят ничего не происходит; игра заканчивается, если 2 хода подряд все
  козлята мертвы.

## Как это работает

| Что | Как сделано |
|---|---|
| процессы | хост запускается первым; каждый козлёнок — потомок хоста, созданный `fork`; номер и pid потомок получает при fork, ответного знакомства нет |
| синхронизация | локальные семафоры `sem_init(pshared=1)` в общей памяти `mmap(MAP_SHARED|MAP_ANONYMOUS)`, созданной до первого fork; на козлёнка два семафора: `down` (волк положил сообщение) и `up` (козлёнок ответил) |
| потоки хоста | поток окна (Qt), поток сигналов (SIGINT/SIGTERM), поток сбора завершившихся потомков, поток игры и **отдельный поток на каждого козлёнка** |
| `pipe` | хост создаёт два `pipe2` до fork; концы наследуются потомком; каждый процесс закрывает чужие концы, потомок дополнительно закрывает все посторонние дескрипторы |
| `fifo` | хост создаёт `/tmp/wolf_<pid>/fifo_N_up` и `fifo_N_down` (`mkfifo`) до fork; после fork хост и потомок **самостоятельно открывают** каналы, как независимые процессы; хост удаляет файлы при завершении |
| `sock` | родственная модификация сокета — `socketpair(AF_UNIX, SOCK_STREAM)` до fork; один конец остаётся у хоста, второй наследуется потомком |
| раунд | волк → `ROUND` (жив ли козлёнок, n), козлёнок → `THROW` (число), волк → `RESULT` (исход и итоги). Сообщение фиксированного размера (44 байта) |
| тайм-ауты | любое ожидание семафора, канала или открытия FIFO — не больше 5 с; затем связь рвётся, козлёнок выходит с кодом 1. Исключение — плановое ожидание ввода волка (3 с) |
| сбои | потомок, не ответивший за 3 с, исключается из игры; завершение, убийство, неверные данные — статусное сообщение в окне и журнале, игра продолжается |
| журнал | stderr (с временем) и syslog (`host_<тип>`, `kid_<тип>#<номер>`); каждый раунд — одной строкой |
| статусы в окне | родился/присоединился, завершился/отключился, игра началась, раунд, игра окончена, все ушли |
| завершение | закрытие окна, Ctrl+C или SIGTERM: козлята получают `BYE`, хост удаляет FIFO, сокеты, разделяемую память и каталог `/tmp/wolf_<pid>` |

### Почему `sock` — это `socketpair`

Для родственных процессов тип «сокеты» имеет специальную модификацию: `socketpair` создаёт
два соединённых конца `AF_UNIX`-сокета, которые наследуются при `fork`. Это тот же тип
взаимодействия (7), но без `bind`/`listen`/`connect` по файловому пути — так же, как `pipe`
является родственной модификацией для программных каналов.

## Сборка

Нужны компилятор C++17, CMake ≥ 3.16, make, Qt 6 (или Qt 5.15) Widgets. Ubuntu / WSL:

```sh
sudo apt install build-essential cmake qt6-base-dev     # Qt 5: qtbase5-dev
make                                                    # то же, что ./build.sh
```

Собираются `host_pipe`, `host_fifo`, `host_sock` с флагами `-Wall -Werror -Wextra`.
Новый файл `src/conn/conn_<тип>.cpp` автоматически даёт `host_<тип>` без правки `CMakeLists.txt`.
Отдельных `client_*` в родственной схеме нет.

## Запуск

```sh
./host_fifo                 # окно волка, в заголовке — pid
./host_fifo --kids 5        # сразу породить 5 козлят
./host_fifo --kids 0        # начать без козлят, добавлять кнопкой
```

Козлята — потомки хоста, поэтому запускать `client_*` не нужно: кнопка «Добавить козлёнка»
вызывает `fork` и создаёт ещё одного. Хост и потомки всегда одного типа (`host_sock` — сокеты
`socketpair`, `host_fifo` — FIFO, `host_pipe` — pipe).

В окне можно ввести число волка и нажать «Бросить» (или Enter) — оно уйдёт в текущий ход.

Параметры для тестов: `--kids N` (0..64), `--turn-ms N` (длительность хода, 100..4000 мс),
`--wolf N` (число волка вместо случайного), `--seed N`; потомки получают производное зерно.

Без дисплея хост запускается с `QT_QPA_PLATFORM=offscreen`. В WSL окно показывает WSLg.

## Тесты

```sh
make test                    # сборка и все тесты
```

Из каталога сборки: `ctest -L unit`, `ctest -L integration`, `ctest -R session -V`.
Отдельные кейсы: `TEST_CASE="S02-fifo G01-sock" bash tests/integration/test_game.sh <каталог сборки>`.

**Unit** (`tests/unit/`, без внешних библиотек):

| Набор | Что проверяет |
|---|---|
| `test_game` | пороги 70/n и 20/n, границы, исходы, счётчики, конец игры после 2 ходов «все мертвы», сброс |
| `test_protocol` | формат сообщения, проверка чужих байтов |
| `test_semaphore` | `sem_init` в общей памяти: post/wait, тайм-аут, видимость из другого процесса, два направления |
| `test_conn_pipe`, `_fifo`, `_sock` | один набор для каждого типа: обмен, 256 КБ, смерть собеседника, запись мёртвому, тайм-аут, очистка файлов, два козлёнка |
| `test_host` | запуск без козлят и добавление потомков на ходу (fork из работающего хоста) |
| `test_hostwindow` | окно (offscreen): ввод числа, кнопка добавления, отсчёт хода, таблица, статусы, вызовы из чужого потока |

**Integration** (`tests/integration/`, каждый кейс для pipe, fifo и sock):

| Набор | Кейсы | Что проверяет |
|---|---|---|
| `test_session` | S01–S07 | без козлят ничего не происходит; 3 и 5 потомков, разные номера; убийство козлёнка; SIGTERM хосту (BYE, удаление файлов); хост убит (потомки выходят по тайм-ауту); аргументы `--kids` и `--help` |
| `test_game` | G01–G04 | каждый раунд по журналу хоста сверяется с правилами (`validate_rounds.awk`); конец игры; хост и потомки видят одни числа; ход волка 3 с |
| `test_build` | B01–B03 | `make` собирает 3 программы и убирает за собой; новый `conn_*` без правки CMake; `-Werror` |

Логи и артефакты упавших кейсов — в `test-logs/`.
