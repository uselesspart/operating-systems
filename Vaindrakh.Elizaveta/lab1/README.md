# Лабораторная работа №1. Disk monitor (вариант 20)

**Вариант задания: 20.**

Программа отслеживает использование файлов в каталогах из конфигурационного
файла. Для наблюдения используется `inotify`, а каждое событие отправляется в
`syslog` с facility `LOG_LOCAL0`. Правило для `rsyslog` направляет эти события
в отдельный файл.

## Структура

```text
lab1/
├── build.sh
├── disk_monitor.conf
├── include/              заголовочные файлы
├── src/                  исходный код демона
├── tests/                модульные и интеграционные тесты
└── rsyslog/30-disk_monitor.conf
```

## Сборка

```sh
./build.sh
```

Скрипт собирает `disk_monitor` с флагами `-Wall -Wextra -Werror` и удаляет
временные объектные файлы после завершения.

## Конфигурация

В конфигурационном файле указывается один каталог в строке. Поддерживаются
комментарии с `#` и необязательный префикс `DIR=`. Относительные пути считаются
от каталога конфигурационного файла.

```text
# пример
/tmp/disk-monitor/watch
DIR=relative/path
```

Подкаталоги отслеживаются рекурсивно. Новые каталоги, созданные после запуска,
тоже автоматически добавляются в `inotify`.

## Запуск и управление

```sh
./disk_monitor /path/to/disk_monitor.conf
```

Если путь не указан, используется `disk_monitor.conf` из текущего каталога.
Абсолютный путь к конфигурации запоминается до демонизации, поэтому после
перехода в `/` обработка `SIGHUP` продолжает работать.

```sh
kill -HUP "$(cat /tmp/disk_monitor.pid)"   # перечитать конфигурацию
kill -TERM "$(cat /tmp/disk_monitor.pid)" # завершить демон
```

При запуске новый экземпляр читает `/tmp/disk_monitor.pid`, проверяет наличие
процесса через `/proc`, отправляет предыдущему экземпляру `SIGTERM` и только
после демонизации записывает собственный PID. Для защиты от случайного
завершения чужого процесса проверяется имя процесса в `/proc`.

## Журналирование

Служебные сообщения демона отправляются с facility `LOG_DAEMON`, а события
файлов — с `LOG_LOCAL0` и идентификатором `disk_monitor`.

Для отдельного файла журнала установите правило один раз:

```sh
sudo cp rsyslog/30-disk_monitor.conf /etc/rsyslog.d/
sudo systemctl restart rsyslog
```

После этого события будут записываться в `/var/log/disk_monitor.log`.

## Тесты

```sh
./tests/run_tests.sh
```

Запускаются модульные тесты разбора конфигурации, форматирования событий и
проверки `/proc`, а также интеграционный тест настоящего демона. Интеграционный
тест проверяет двойную демонизацию, `/dev/null`, PID-файл, обработку файловых
событий, перезагрузку конфигурации через `SIGHUP` и завершение через `SIGTERM`.
