# Лабораторная работа 1. Демон «Напоминалка» (вариант 19)

Демон проверяет события из конфигурационного файла каждые 10 секунд. Новые напоминания добавляются с помощью специального скрипта в формате `add_event date time [flag] text`, где `flag` — необязательное поле. Флаги `-h`, `-d`, `-w` задают повтор напоминаний каждый час, день и неделю соответственно. В указанное время демон открывает новый терминал и выводит заданный текст.

## Возможности

- Демонизация через `fork()` и `setsid()`.
- Singleton-класс `Daemon`, управляющий жизненным циклом процесса.
- Добавление событий с помощью `add_event.sh`.
- Перечитывание конфигурации по `SIGHUP` без перезапуска процесса.
- Завершение по `SIGTERM` с записью в системный журнал.
- Защита от одновременной работы экземпляров через PID-файл и `flock()`.
- Системное журналирование и два набора автоматических тестов.

## Требования

- Linux; проект разрабатывался для Ubuntu.
- Компилятор `g++` с поддержкой C++17.
- Bash и стандартные утилиты Ubuntu.
- Графическая сессия с доступным `x-terminal-emulator` или `gnome-terminal` для отображения настоящих напоминаний.

Демон запускается от имени обычного пользователя из терминала графической сессии. Права root для обычной работы и тестов не требуются. В среде без графического интерфейса процесс может работать, но открыть окно напоминания не сможет.

## Сборка

Из корня репозитория:

```bash
bash build.sh
```

Альтернативный способ — назначение скриптам права на выполнение и прямой запуск:

```bash
chmod +x build.sh add_event.sh
./build.sh
```

Скрипт собирает все рабочие исходники в один файл `mydaemon` с флагами:

```text
-std=c++17 -Wall -Werror
```

Перед сборкой удаляется предыдущий `mydaemon`. Промежуточные объектные файлы в каталоге проекта не создаются.

## Конфигурация

Программа принимает путь к конфигурационному файлу обязательным аргументом. Формат файла:

```text
interval=10

# Одноразовое напоминание.
add_event 2030-01-15 12:30 Проверить лабораторную

# Повторяющиеся напоминания.
add_event 2030-01-15 13:00 -h Выпить воды
add_event 2030-01-15 18:00 -d Проверить почту
add_event 2030-01-20 10:00 -w Подвести итоги недели
```

Даты в примере приведены для иллюстрации формата. Для проверки срабатывания используются актуальные дата и время.

| Поле | Значение |
| --- | --- |
| `interval` | Положительный целый интервал проверки в секундах |
| `date` | Дата в формате `YYYY-MM-DD` |
| `time` | Локальное время компьютера в формате `HH:MM` |
| `flag` | Необязательный флаг повторения |
| `text` | Непустой текст напоминания |

| Флаг | Повторение |
| --- | --- |
| Без флага | Одноразовое событие |
| `-h` | Каждый час |
| `-d` | Каждые 24 часа |
| `-w` | Каждые 168 часов |

Пустые строки и строки, начинающиеся после пробелов с `#`, игнорируются. Интервал обязателен. Загрузчик проверяет дату и время, наличие текста и известность команды.

Путь к конфигурации преобразуется в абсолютный до смены рабочей директории на `/`. Поэтому последующий `SIGHUP` перечитывает тот же файл.

## Запуск и управление

Из корня репозитория:

```bash
./mydaemon ./config.conf
```

Можно передать другой файл:

```bash
./mydaemon /absolute/path/to/config.conf
```

После отделения дочернего процесса команда возвращает управление терминалу. Демон продолжает работу в фоне, а его PID записывается в `/tmp/mydaemon.pid`. Окончательный результат инициализации определяется по состоянию процесса и сообщениям системного журнала.

Просмотр PID и состояния процесса:

```bash
cat /tmp/mydaemon.pid
ps -p "$(cat /tmp/mydaemon.pid)" -o pid,ppid,sid,tty,stat,args
```

Команды управления выполняются при работающем демоне и непустом PID-файле:

```bash
# Перечитать конфигурацию.
kill -HUP "$(cat /tmp/mydaemon.pid)"

# Завершить работу.
kill -TERM "$(cat /tmp/mydaemon.pid)"
```

Повторный запуск той же команды заменяет предыдущий экземпляр:

```bash
./mydaemon ./config.conf
```

PID-файл защищён `flock()`. Если он заблокирован другим экземпляром, программа читает PID, проверяет `/proc/<PID>`, отправляет `SIGTERM` и ожидает освобождения блокировки. Новый PID записывается после демонизации. При штатном завершении содержимое PID-файла очищается; сам файл остаётся.

После аварийного завершения, например `SIGKILL`, PID может остаться в файле. Если блокировка свободна, следующий запуск игнорирует старое содержимое и записывает новый PID.

## Добавление напоминаний

Скрипт запускается из каталога, содержащего используемый `config.conf`:

```bash
bash add_event.sh 2030-01-15 12:30 "Проверить лабораторную"
bash add_event.sh 2030-01-15 13:00 -h "Выпить воды"
bash add_event.sh 2030-01-15 18:00 -d "Проверить почту"
bash add_event.sh 2030-01-20 10:00 -w "Подвести итоги недели"
```

Скрипт дописывает строку в `./config.conf`. Если PID-файл указывает на доступный процесс, скрипт отправляет ему `SIGHUP`. Если демон не запущен, событие остаётся в файле для следующего запуска.

Если демон использует другой конфигурационный файл, события добавляются непосредственно в этот файл, после чего процессу вручную отправляется `SIGHUP`. Текущая версия скрипта не принимает путь к конфигурации.

В момент обработки наступившего события демон запускает терминал, выводит текст и предлагает нажать Enter для закрытия окна. Текст передаётся отдельным аргументом, а не вставляется в shell-команду.

## Системный журнал

Для журналирования используются `openlog()`, `syslog()` и `closelog()`. Идентификатор сообщений — `my_daemon`, facility — `LOG_DAEMON`. В журнал записываются сообщения о запуске, перечитывании конфигурации, ошибках и завершении работы.

Последние сообщения:

```bash
journalctl -t my_daemon --since "10 minutes ago" --no-pager
```

Наблюдение в реальном времени:

```bash
journalctl -t my_daemon -f
```

## Тестирование

Тесты разделены на два набора. Сторонние тестовые библиотеки не используются.

### Проверки конфигурации

```bash
bash tests/run_config_tests.sh
```

Скрипт отдельно собирает `ConfigLoaderTests.cpp` вместе с настоящим `ConfigLoader.cpp`, используя `-std=c++17 -Wall -Werror`. Исполняемый файл и конфигурации создаются во временных каталогах и удаляются после проверки. Рабочий `config.conf` не изменяется.

| Группа | Что проверяется |
| --- | --- |
| Корректная конфигурация | Интервал, дата, время, текст и отсутствие повтора без флага |
| Флаги повторения | Разбор `-h`, `-d`, `-w` и удаление флага из текста |
| Комментарии и пустые строки | Пропуск комментариев и обработка внешних пробелов |
| Ошибочный интервал | Отсутствующий, нулевой, отрицательный и нечисловой интервал |
| Ошибочные события | Несуществующая дата, неизвестная команда и пустой текст |

### Проверки демона

Перед проверкой обычный экземпляр демона должен быть остановлен. Тесты используют общий PID-файл и отказываются работать, если он непустой. Наборы запускаются последовательно, от имени обычного пользователя, без `sudo`.

```bash
bash build.sh
bash tests/run_daemon_tests.sh
```

| Проверка | Ожидаемое поведение |
| --- | --- |
| Запуск | PID-файл указывает на работающий исполняемый файл демона в `/proc` |
| `SIGTERM` | Процесс завершается, PID-файл очищается |
| Повторный запуск | Новый экземпляр заменяет старый |
| `SIGHUP` | Новое событие загружается без смены PID и выполняется один раз |
| `add_event.sh` | Событие добавляется скриптом, текст передаётся без изменений, повторного выполнения нет |

Вместо графического терминала тест подставляет временный `x-terminal-emulator`, записывающий аргументы в файл. Это позволяет проверить текст автоматически. Реальное окно терминала, выполнение команды внутри него и записи системного журнала проверяются отдельно вручную.

Тестовый конфиг использует интервал 1 секунда и уже наступившие события, чтобы проверки выполнялись быстро. Рабочий интервал 10 секунд и основной конфиг не меняются. Проверки демона обычно занимают около 10 секунд. При ошибке скрипт возвращает ненулевой код и выводит путь к сохранённым временным файлам.

Успешный итог каждого набора:

```text
Passed: 5, failed: 0
```

Запуск обоих наборов:

```bash
bash tests/run_config_tests.sh
bash build.sh
bash tests/run_daemon_tests.sh
```

Тестовая программа имеет собственный `main()` и собирается отдельно. Добавлять её в `build.sh` не нужно.

## Особенности текущей реализации

- Проверка выполняется периодически, поэтому напоминание может появиться с задержкой около одного интервала, а не точно на границе минуты.
- Уже наступившее одноразовое событие показывается при первой проверке. Для повторяющегося события выбирается последнее наступившее повторение; все пропущенные повторения подряд не воспроизводятся.
- История срабатываний хранится в памяти. После перезапуска прошедшие события могут показаться снова. Изменение номера строки или содержимого события также меняет его внутренний ключ.
- Повторы на день и неделю реализованы через фиксированные 24 и 168 часов.
- При ошибке перечитывания конфигурации демон продолжает работать с предыдущей успешно загруженной конфигурацией.
