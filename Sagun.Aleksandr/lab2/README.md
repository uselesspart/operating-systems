# Лабораторная работа 2. Межпроцессное взаимодействие в Linux — локальный чат (вариант 18)

Локальный чат на C++17 и Qt 6 для Ubuntu. Хост создаёт клиентские процессы через `fork()` и открывает отдельное окно для каждого участника. В общем чате сообщения видят все. При личной переписке текст видят только отправитель и адресат, в том числе когда клиент пишет другому клиенту через хост.

Вариант 18 объединяет сценарий 2 «Чат», родственную конфигурацию «один ко многим» и три механизма IPC. Механизм выбирается при запуске. Все три версии используют один интерфейс чата и один формат сообщений.

## Сборка и первый запуск

Для сборки нужны CMake версии 3.16 или новее, GNU Make, Bash, компилятор с поддержкой C++17 и Qt 6 Widgets. Для открытия окон нужна графическая сессия Ubuntu. При необходимости установите зависимости:

```bash
sudo apt update
sudo apt install build-essential cmake qt6-base-dev
```

Из корня учебного репозитория выполните:

```bash
cd Sagun.Aleksandr/lab2
make
./bin/host_pipe --clients 2
```

Откроются три окна — «Хост», «Клиент 1» и «Клиент 2». В окне клиента 1 выберите в поле «Кому» клиента 2, введите текст и нажмите Enter. Сообщение появится по одной строке в двух клиентских окнах. Чтобы написать всем участникам, выберите «Общий чат». Отправка кнопкой «Отправить» работает так же, как Enter.

## Три способа передачи сообщений

Команды выполняются из каталога лабораторной. Закрывайте окно хоста между запусками, чтобы видеть окна одной группы.

| Запуск | Механизм | Что соединяет хост с одним клиентом |
|---|---|---|
| `./bin/host_pipe --clients 2` | Неименованные каналы, тип 5 | Два вызова `pipe()` до `fork()`. По одному каналу данные идут к хосту, по второму — к клиенту. |
| `./bin/host_fifo --clients 2` | Именованные каналы, тип 6 | После `fork()` хост создаёт FIFO `to-host` и `to-client` через `mkfifoat()`. Каждый процесс открывает свои концы. При штатном завершении хост удаляет оба FIFO и временный каталог. |
| `./bin/host_sock --clients 2` | Unix-сокеты, тип 7 | Одна двусторонняя пара `socketpair(AF_UNIX, SOCK_SEQPACKET, …)`. Родитель и потомок сохраняют по одному концу. |

`--clients N` задаёт положительное число клиентов при старте. Без аргументов хост создаёт одного клиента. Для FIFO готовность сторон согласуется межпроцессными семафорами. Ожидание при открытии соединения ограничено пятью секундами.

## Как устроен чат

- **Процессы и потоки.** Хост запускает клиентов до создания своего окна Qt. Затем для каждого клиентского соединения создаётся отдельный поток чтения `ClientReader`. Обновление окна и выбор получателей выполняются в главном потоке хоста.
- **Личная доставка.** Хост получает сообщение по соединению отправителя, проверяет адрес и пересылает текст адресату и автору. Хост показывает личное сообщение в своём окне, только если сам участвует в этой переписке. Если выбранный клиент уже вышел, отправитель получает сообщение об ошибке.
- **Порядок истории.** При отправке окно ставит метку общих для этих процессов часов `CLOCK_MONOTONIC`. Получатель вставляет запись в историю по этой метке, включая случай запоздавшей доставки. Номер `#` назначает хост при обработке. При равных метках он определяет порядок строк.
- **Бездействие.** Хост отслеживает каждого клиента отдельно. Если тот больше 60 секунд не отправлял сообщений, хост завершает его через `SIGKILL`. Чтение чужой переписки таймер не сбрасывает. Хост показывает статус отключения и продолжает работу с остальными участниками.
- **Формат данных.** Перед каждым сообщением записывается двухбайтовая длина. Это позволяет разобрать одну запись, пришедшую частями, или несколько записей за одно чтение. Внутри сообщения передаются отправитель, адресат, номер, время и текст. Предел пользовательского текста — 4000 байт UTF-8.

## Основные файлы проекта

```text
lab2/
├── Makefile                # Точка входа для команды make
├── build.sh                # Временный каталог сборки и запуск CMake
├── CMakeLists.txt          # Общие исходники, цели host_* и frame_check
├── README.md
├── .gitignore
├── src/
│   ├── host.cpp            # main(), создание клиентов и завершение процессов
│   ├── chat/               # frame — границы записей, message — поля сообщения
│   ├── ipc/
│   │   ├── connection.*    # Общий интерфейс, отправка и приём кадров
│   │   ├── conn_pipe.cpp   # Неименованные каналы
│   │   ├── conn_fifo.cpp   # Именованные каналы
│   │   └── conn_sock.cpp   # Unix-сокеты
│   ├── runtime/            # Сессии клиентов, потоки чтения, маршрутизация и таймеры
│   └── ui/                 # Окно Qt, выбор адресата и история переписки
└── tests/
    └── frame_check.cpp     # Автоматическая проверка разбора кадров
```

Команда `make` вызывает `build.sh`. Скрипт собирает проект во временном каталоге, помещает исполняемые файлы в `bin/` рядом с `Makefile` и удаляет промежуточный каталог при выходе. CMake собирает исходники с флагами `-Wall -Wextra -Werror` и формирует отдельную цель `host_*` для каждой реализации `src/ipc/conn_*.cpp`.

## Проверка

### Автоматическая проверка кадров

```bash
./bin/frame_check
```

Ожидаемый вывод — `frame_check: OK`. Тест проверяет получение заголовка и текста по частям, два кадра подряд, кириллицу, допустимую длину тела 4096 байт и отказ при недопустимой длине. Далее приведены отдельные проверки поведения самого чата.

### Видимость сообщений

Запустите каждый из трёх вариантов с `--clients 2`. Галочка означает одну копию сообщения в истории, прочерк — отсутствие текста.

| Отправка | Хост | Клиент 1 | Клиент 2 |
|---|:---:|:---:|:---:|
| Клиент 1 → Общий чат | ✓ | ✓ | ✓ |
| Клиент 1 → Клиент 2 | — | ✓ | ✓ |
| Клиент 2 → Хост | ✓ | — | ✓ |
| Хост → Клиент 1 | ✓ | ✓ | — |

### Отключение и очистка

1. На новом запуске оставьте клиента 1 читающим. Примерно на 40-й секунде отправьте с клиента 2 личное сообщение хосту. Через минуту с небольшим после старта клиент 1 закроется. Клиент 2 сможет продолжить переписку.
2. При запуске `host_fifo` терминал печатает путь к временному каталогу каждой пары FIFO. Пока чат открыт, в каждом таком каталоге есть `to-host` и `to-client`. Закройте хоста — оставшиеся клиентские окна закроются, а напечатанные каталоги будут удалены.

<details>
<summary>Как воспроизвести доставку в обратном порядке</summary>

Запустите свежий `./bin/host_fifo --clients 2` и дождитесь появления обоих клиентов. В другом терминале Ubuntu выполните блок в Bash и вставьте **первый** путь из строк `FIFO directory` хоста. Сделайте это в течение минуты, пока клиенты подключены.

```bash
{
    read -r -p 'Первый каталог FIFO: ' fifo_dir
    if [[ -p "$fifo_dir/to-host" ]]; then
        {
            printf '\000\020%s' $'1 -1 0 20\nSECOND'
            printf '\000\017%s' $'1 -1 0 10\nFIRST'
        } > "$fifo_dir/to-host"
    else
        echo 'FIFO клиента 1 не найден'
    fi
}
```

В канал сначала записывается общий тестовый кадр `SECOND` с меткой 20, затем `FIRST` с меткой 10. Если это первые сообщения с момента запуска, после обработки обоих кадров верхней строкой переписки будет `#2 Клиент 1: FIRST`, под ней — `#1 Клиент 1: SECOND`. Так проверяется случай, когда хост получает более раннее сообщение вторым.
