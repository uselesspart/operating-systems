# Лабораторная работа 1. Процессы, демонизация процессов

Вариант 19 — «Напоминалка».

Демон раз в 10 секунд проверяет файл событий. Когда время события наступает,
демон открывает новый терминал и показывает текст напоминания. События
добавляются скриптом `add_event.sh` в формате `add_event date time [flag] text`,
где необязательный флаг `-h`, `-d` или `-w` задаёт повтор каждый час, день или
неделю.

## Сборка

Нужны Linux, компилятор с поддержкой C++17 и CMake не ниже 3.16.

```sh
./build.sh
```

Скрипт собирает проект во временном каталоге, удаляет промежуточные файлы и
оставляет только готовый `./reminder_daemon`. Если права на запуск скриптов
потерялись при копировании, их нужно вернуть:

```sh
chmod +x add_event.sh stop.sh build.sh tests/run_tests.sh
```

## Запуск

Демон запускается из каталога, где лежит `events.conf`:

```sh
./reminder_daemon
```

Можно передать другой файл событий аргументом:

```sh
./reminder_daemon /path/to/events.conf
```

Переменная `REMINDER_CONFIG` задаёт файл событий, если аргумент не указан.

Добавление напоминаний:

```sh
./add_event.sh 2026-10-24 15:30 "Пара в ГЗ Политеха"
./add_event.sh 2026-10-25 09:00 -d "Перекус"
./add_event.sh 2026-10-26 18:00 -h "Еще пара"
./add_event.sh 2026-11-01 12:00 -w "Встретиться с Филом"
```

Скрипт проверяет дату, время, флаг и текст, переводит дату и время в UNIX-время
и дописывает строку в файл. Запись идёт под блокировкой `events.conf.lock`,
поэтому событие не теряется, если демон в этот момент переписывает файл. Если
демон запущен, скрипт отправляет ему `SIGHUP`, чтобы событие подхватилось сразу.

Остановка:

```sh
./stop.sh
```

Либо вручную:

```sh
kill -TERM "$(cat "${XDG_RUNTIME_DIR:-/tmp}/reminder_daemon.pid")"
```

PID-файл находится в `$XDG_RUNTIME_DIR/reminder_daemon.pid`, а если переменная
не задана — в `/tmp/reminder_daemon.pid`. Повторный запуск демона останавливает
предыдущий экземпляр по PID-файлу.

## Файл событий

Одна строка — одно событие:

```text
<timestamp> <repeat> <text>
```

- `timestamp` — UNIX-время ближайшего срабатывания;
- `repeat` — `none`, `hour`, `day` или `week`;
- `text` — текст напоминания до конца строки, может содержать пробелы.

Пустые строки и строки, начинающиеся с `#`, пропускаются. Пример лежит в
`events.conf.example`. В рабочем `events.conf` уже есть одно событие.

При срабатывании одноразовое событие удаляется из файла, а повторяющееся
сдвигается на час, день или неделю вперёд. Если демон был выключен и время
повторяющегося события уже прошло, оно сдвигается до ближайшего будущего
момента, а не срабатывает несколько раз подряд.

## Сигналы и журнал

- `SIGHUP` — перечитать файл событий;
- `SIGTERM` и `SIGINT` — завершить работу и удалить PID-файл.

Сообщения о запуске, срабатываниях, ошибках и завершении пишутся в системный
журнал через `openlog`, `syslog` и `closelog` с идентификатором
`reminder_daemon`:

```sh
journalctl -t reminder_daemon --since "10 minutes ago"
journalctl -t reminder_daemon -f
```

## Терминал

Для показа напоминания демон запускает `x-terminal-emulator`, `xterm`, `konsole`
или `gnome-terminal` — первый найденный. Текст передаётся отдельным аргументом,
а не вставляется в командную строку, поэтому кавычки и символы shell в тексте
безопасны. Окно остаётся открытым до нажатия Enter.

Переменная `REMINDER_TERMINAL` позволяет указать другой терминал, например для
проверки без графической сессии:

```sh
REMINDER_TERMINAL=/path/to/terminal ./reminder_daemon
```

Демон нужно запускать от обычного пользователя из графической сессии, чтобы
ему были доступны `DISPLAY` или `WAYLAND_DISPLAY`. В системе без графической
среды он работает, но окно показать не сможет.

## Тесты

```sh
./tests/run_tests.sh
```

Скрипт собирает проект во временном каталоге, запускает `ctest` и удаляет
каталог сборки. Если нужно вручную:

```sh
cmake -S . -B /tmp/reminder-build
cmake --build /tmp/reminder-build
(cd /tmp/reminder-build && ctest --output-on-failure)
rm -rf /tmp/reminder-build
```

Unit-тесты проверяют разбор строк событий, расчёт повторов и чтение/запись
файла. Интеграционные тесты запускают настоящий демон с подставным терминалом
и проверяют срабатывание, повтор, `SIGHUP`, `SIGTERM`, повторный запуск и
работу `add_event.sh`.

## Ограничения

- Время в событии задаётся с точностью до минуты, проверка идёт раз в 10 секунд,
  поэтому напоминание может появиться с задержкой до 10 секунд.
- Если файл событий повреждён, демон пишет ошибку в журнал и продолжает работу
  с последним успешно прочитанным списком событий.
- При перезаписи файла комментарии в нём не сохраняются.
- Повтор «день» и «неделя» — это фиксированные 24 и 168 часов, а не календарные
  сутки.
