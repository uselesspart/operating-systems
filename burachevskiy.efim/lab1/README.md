# Лабораторная работа № 1. Процессы, демонизация

**Вариант 19 — «Напоминалка».** Демон проверяет события каждые 10 секунд и открывает новый терминал с текстом напоминания. Поддерживаются одноразовые события и повторения каждый час, день или неделю.

## Требования

Linux 5.3+, Bash, g++ с поддержкой C++17 и графическая сессия пользователя. Поддерживаемые терминалы: Ptyxis, GNOME Terminal, GNOME Console (`kgx`), Konsole, XFCE Terminal, xterm.

## Сборка

Из каталога `burachevskiy.efim/lab1`:

```bash
./build.sh
```

Результат — исполняемый файл `reminder`. Флаги компиляции: `-std=c++17 -Wall -Wextra -Werror -O2`. Промежуточные файлы удаляются автоматически.

## Конфигурация

Файл `events.conf`:

```text
interval=10
terminal=auto
2026-11-01 18:30 - "Одноразовое событие"
2026-11-01 09:00 -d "Ежедневное событие"
```

`interval` — интервал проверки в секундах, `terminal` — имя или абсолютный путь поддерживаемого терминала. Значение `auto` включает автоматический выбор.

Дата задаётся в формате `YYYY-MM-DD`, время — `HH:MM` или `HH:MM:SS`, в местном часовом поясе. В файле текст заключается в двойные кавычки, отсутствие повторения обозначается `-`.

## Добавление событий

```bash
./add_event 2026-11-01 18:30 "Текст напоминания"
./add_event 2026-11-01 09:00 -d "Ежедневное напоминание"
```

Необязательные флаги: `-h` — каждый час, `-d` — каждый день, `-w` — каждую неделю. Скрипт добавляет запись в `events.conf` рядом с собой. Другой файл задаётся переменной `REMINDER_CONFIG`. Новые события обнаруживаются при очередной проверке.

## Запуск и управление

```bash
./reminder --check events.conf
./reminder events.conf
```

Запуск выполняется из терминала графической сессии без `sudo`. Для работы в переднем плане используется `./reminder --foreground events.conf`. Enter закрывает окно напоминания.

```bash
kill -HUP "$(head -n 1 events.conf.pid)"
kill -TERM "$(head -n 1 events.conf.pid)"
journalctl -t reminder --no-pager
```

`SIGHUP` перечитывает конфигурацию; при ошибке сохраняются прежние настройки. `SIGTERM` завершает демон с записью в системный журнал. Повторный запуск завершает предыдущий экземпляр и записывает новый PID после демонизации.

PID хранится в первой строке `events.conf.pid`; после завершения файл остаётся пустым. Файл `events.conf.state` сохраняет обработанные срабатывания между запусками. Просроченные события показываются один раз; для повторяющихся обрабатывается последнее наступившее срабатывание.

## Проверка

```bash
./test.sh
```

Тесты на C++ проверяют конфигурацию, даты, повторения, добавление событий, демонизацию, сигналы, PID-файл, перезапуск и ошибки терминала. Скрипт возвращает ненулевой код при ошибках.

Открытие настоящего окна проверяется вручную: добавить событие на минуту вперёд, запустить демон, закрыть исходный терминал и дождаться напоминания.
