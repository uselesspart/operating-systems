# reminderd — демон-напоминалка (Linux / WSL)

Фоновый процесс (демон), который читает события из конфигурационного файла и в нужное время
открывает новый терминал с текстом напоминания.

## Формат конфигурационного файла (`reminder.conf`)

```
ГГГГ-ММ-ДД ЧЧ:ММ[:СС] [-h|-d|-w] текст
```

`-h` — повтор каждый час, `-d` — каждый день, `-w` — каждую неделю. Строки с `#` и пустые игнорируются.

Добавлять события нужно скриптом (он проверяет формат, дописывает строку в конфиг и посылает демону SIGHUP):

```
./add_event.sh 2030-05-17 09:30 Позвонить маме
./add_event.sh 2030-05-17 09:30 -d Выпить воды
```

## Структура

| Файл | Назначение |
|------|-----------|
| `src/main.cpp` | точка входа |
| `src/Daemon.h/.cpp` | класс-синглтон `Daemon`: pid-файл, демонизация, сигналы, syslog, запуск терминала |
| `src/Event.h/.cpp` | разбор конфига и расчёт времени срабатывания |
| `build.sh` | сборка (`g++ -Wall -Werror`), промежуточные файлы удаляются |
| `add_event.sh` | добавление события в конфиг |
| `tests/run_tests.sh` | запуск всех тестов (модульные + интеграционные) |

## Сборка и запуск

```
bash build.sh
./reminderd            # конфиг: ./reminder.conf (или ./reminderd путь/к/конфигу)
```

* `kill -HUP <pid>` — перечитать конфиг, `kill -TERM <pid>` — завершить (pid в `/tmp/reminderd_<uid>.pid`).
* Повторный запуск: новый экземпляр находит старый по pid-файлу, проверяет `/proc`, шлёт SIGTERM и занимает его место.
* Журнал: `grep reminderd /var/log/syslog` (нужен rsyslog) или `journalctl -t reminderd` (если есть systemd).
