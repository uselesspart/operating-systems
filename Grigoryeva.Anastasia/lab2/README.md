# Лабораторная 2. Межпроцессное взаимодействие в Linux

**Вариант 10** (20 баллов): сценарий 1 «Волк и семеро козлят», конфигурация «Независимые. Один ко многим»,
типы взаимодействия **5 — pipe, 6 — fifo, 7 — sock** (реализованы все три, т.е. без потери баллов).

* **Хост** (`host.cpp`, GUI на Qt) — волк. Запускается первым, обслуживает любое число козлят
  (на каждого — отдельный поток), ведёт всю игровую логику и показывает ход игры.
* **Клиент** (`client.cpp`) — козлёнок, независимый процесс; при запуске получает pid хоста.
* Знакомство: **двустороннее, через сигналы** (SIGUSR1 + `sigqueue`). Синхронизация: **глобальные семафоры** (`sem_open`).

## Правила игры (как реализованы)

1. До подключения козлят ничего не происходит. Козлята могут присоединяться в любой момент.
2. Ход: волк бросает число 1–100 — вводит его пользователь в окне хоста; если за **3 с** число не введено,
   выбирается случайно. Затем каждый козлёнок присылает число (живые 1–100, мёртвые 1–50).
3. n — число козлят в раунде. Живой прячется, если `|число − волк| ≤ 70/n`, иначе попадается и становится мёртвым.
   Мёртвый воскресает, если `|число − волк| ≤ 20/n`.
4. В каждом раунде в GUI выводятся: число волка, числа козлят, число **спрятавшихся / попавшихся / мёртвых / воскресших**.
5. Игра заканчивается, если **2 хода подряд все козлята мертвы**. Козлята получают сообщение об окончании и завершаются.

### Как устроены типы взаимодействия

* **pipe.** Анонимный канал нельзя передать независимому процессу через `fork`, поэтому хост создаёт две пары `pipe()` на
  клиента и переносит их дескрипторы на фиксированные номера `1000 + 4·id + {0..3}`; клиент (знает pid хоста и свой id)
  открывает нужные концы через `/proc/<pid хоста>/fd/<номер>` — это тот же самый канал.
* **fifo.** Два именованных канала на клиента `/tmp/wolf_<pid>_<id>_h2c.fifo` и `_c2h.fifo`; хост удаляет файлы при завершении работы с клиентом.
* **sock.** Сокет `AF_UNIX` `/tmp/wolf_<pid>_<id>.sock`: хост слушает, клиент подключается, `accept` — при первой операции.
* В каждом типе порядок чтения/записи задают два **глобальных семафора** (`/wolf_<pid>_<id>_h2c`, `_c2h`): записал → `sem_post`, читатель → `sem_timedwait` (5 с).

### Знакомство и тайм-ауты

1. Клиент блокирует SIGUSR1 и посылает его хосту (повтор каждые 1.5 с — стандартные сигналы могут слипаться; хост отвечает на повтор тем же id).
2. Хост (поток приёма, `sigtimedwait`) узнаёт pid клиента из `siginfo`, выдаёт id (1, 2, 3…), создаёт `Conn` и отвечает `sigqueue(SIGUSR1)` со значением = id.
3. Клиент ждёт ответ **не более 5 с**, получает id, открывает `Conn` и шлёт `HELLO`.
4. Все ожидания (семафоры, чтение, запись, знакомство) — **5 секунд**; при превышении связь прерывается, клиент останавливается (код 2),
   хост отключает козлёнка и продолжает работу.
5. Чтобы здоровый клиент не отваливался, пока волк выбирает число, хост шлёт ему `PING` раз в секунду.

## Сборка в WSL (Ubuntu) + VS Code

```bash
sudo apt update
sudo apt install -y build-essential cmake qt6-base-dev     # Ubuntu 22.04+; если нет Qt6: qtbase5-dev
```

Сборка (оба варианта делают одно и то же):

```bash
./build.sh        # или просто:  make
```

Исполняемые файлы появятся в `bin/`: `host_pipe host_fifo host_sock client_pipe client_fifo client_sock` (+ `unit_*` тесты).
CMake создаёт временные файлы в отдельном каталоге, `build.sh` удаляет его сам. Любой новый `src/conn_<тип>.cpp`
подхватывается автоматически и даёт новую пару `host_<тип>` / `client_<тип>`.

Хост без Qt (консольный режим): `./build.sh --no-gui`.

> GUI в WSL требует WSLg (Windows 11 или свежий WSL на Windows 10: `wsl --update`). Если Qt не стартует с ошибкой про плагин `xcb`: `sudo apt install libxcb-cursor0`.
> Работайте в файловой системе Linux (`~/lab2`), а не в `/mnt/c/...`.

## Запуск

Терминал 1 — хост (откроется окно волка):

```bash
./bin/host_pipe           # или host_fifo / host_sock
```

В окне хоста виден pid. Терминалы 2, 3, … — козлята (по одному процессу на терминал, можно подключать «на ходу»):

```bash
./bin/client_pipe <pid_хоста>
./bin/client_pipe <pid_хоста>
```

В каждом ходу введите число волка и нажмите «Бросить число» (3 секунды), иначе оно выберется случайно.

Параметры хоста: `--wolf N` (фиксированное число волка, без ввода), `--wait-kids K`, `--round-delay MS`, `--wolf-timeout MS`, `--max-rounds N`.
Параметры клиента: `--numbers ЖИВОЙ,МЕРТВЫЙ` (фиксированные числа), `--seed N`.

Примечание: два клиента, запущенных в одну и ту же микросекунду, могут слить SIGUSR1 в один — клиент автоматически повторяет запрос.
Коды возврата клиента: 0 — игра окончена, 1 — не удалось подключиться, 2 — связь потеряна. Сообщения пишутся в журнал (stdout) и в GUI хоста.

## Тесты

```bash
make test         # или: bash tests/run_tests.sh
```

Тесты собирают хост в консольном режиме (Qt не нужен) во временный каталог и запускают:

* `unit_rules` — правила игры (границы порогов 70/n и 20/n, допустимые числа);
* `unit_conn_<тип>` — для каждого типа: обмен сообщениями, порядок, блокирующее чтение, поток из 2000 сообщений,
  тайм-аут чтения, ошибка без хоста, удаление семафоров;
* `tests/test_game.sh` — настоящие процессы `host_*`/`client_*` для pipe, fifo, sock: полная игра, три козлёнка,
  воскрешение, подключение на ходу, `kill -9` клиента, `SIGTERM` хоста, `kill -9` хоста (клиент останавливается по тайм-ауту),
  отсутствие мусора в `/dev/shm` и `/tmp`, тайм-аут знакомства 5 с, неверные аргументы.

Для ускорения тестов тайм-аут можно уменьшить переменной окружения `WOLF_IO_TIMEOUT_MS` (по умолчанию 5000).

## Ограничения

* Для `pipe` на хост приходится 4 дескриптора на клиента (номера от 1000); хост поднимает `RLIMIT_NOFILE` до жёсткого лимита (в WSL хватает на сотни клиентов).
* Все процессы должны быть запущены одним пользователем (доступ к `/proc/<pid>/fd`, файлы в `/tmp` с правами 0600).
