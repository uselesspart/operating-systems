# Лабораторная работа 1: Создание демонов в системе linux (Disk monitor)

## Описание задания
**Вариант 20**: Разработать системную службу (демона) для Linux на языке C++, которая отслеживает изменения в заданной директории (создание, удаление, модификация файлов).
Программа должна работать в фоновом режиме, корректно обрабатывать сигналы завершения (SIGTERM) и использовать системный журнал (`syslog`) для записи событий.

**Реализованный функционал:**

* Демонизация процесса с корректным закрытием файловых дескрипторов и отвязкой от терминала.
* Использование Linux API `inotify` для асинхронного перехвата событий файловой системы в неблокирующем режиме (`select`).
* Настройка маршрутизации логов через `rsyslog` (категория `LOG_LOCAL0`).
* Изолированная сборка и тестирование с использованием Docker.
* Написаны Unit-тесты (GTest) и bash-скрипт для интеграционного тестирования демона.

## Требования

* **ОС:** Linux (Ubuntu/Debian)
* **Инструменты:** `cmake`, `make`, `g++` (с поддержкой C++17 и выше)
* **Зависимости:** `rsyslog`, `inotify-tools` (для тестов)
* Для безопасной проверки и избежания конфликтов с системным окружением рекомендуется использовать Docker.

## Конфигурирование

Демон получает пути к отслеживаемым директориям из конфигурационного файла. По умолчанию пример конфигурации находится в `configs/disk-monitor.conf`.

**Формат конфигурационного файла:**

```ini
# Укажите абсолютные пути к директориям для мониторинга
DIR=/tmp/test_monitor_dir
DIR=/var/www/html
```

*Примечание: Если файл не передан при запуске, программа завершится с ошибкой.*

## Сборка и тестирование (Рекомендуемый способ)

Проект включает автоматизированный bash-скрипт, который собирает изолированный контейнер с необходимым окружением (Ubuntu 24.04), компилирует код и прогоняет все уровни тестов.

Для запуска проверки выполните в корне проекта:

```bash
chmod +x docker_test.sh
./docker_test.sh
```

**Скрипт выполнит следующие шаги:**

1. Сборка Docker-образа с установкой компиляторов, GTest и `rsyslog`.
2. Настройка `rsyslog` для записи логов демона в `/var/log/disk_monitor.log`.
3. Компиляция проекта через CMake (скрипт `build.sh`).
4. Запуск Unit-тестов (`run_tests.sh`).
5. Запуск интеграционного теста `integration_test.sh` (старт демона, генерация событий ФС, проверка логов, корректное завершение по SIGTERM).

## Локальная сборка и ручной запуск

Если вы хотите собрать и запустить демона непосредственно на хост-машине (Linux), выполните следующие шаги.

### 1. Сборка

В проекте предусмотрен скрипт `build.sh`, который автоматически подготавливает директорию `build`, запускает CMake и переносит готовые артефакты в директорию `out/`.

```bash
chmod +x build.sh
./build.sh
```

### 2. Запуск демона

После успешной сборки исполняемый файл появится в папке `out/`. Запустите его, передав путь к конфигурационному файлу:

```bash
./out/disk_monitor configs/disk-monitor.conf
```

Демон мгновенно уйдет в фоновый режим. Узнать его PID можно из системного лога или посмотрев содержимое PID-файла (по умолчанию `/tmp/disk_monitor.pid`).

### 3. Просмотр логов

Для просмотра событий мониторинга в реальном времени, выполните:

```bash
# Если настроен rsyslog для LOG_LOCAL0:
tail -f /var/log/disk_monitor.log

# Если используется стандартная конфигурация системы:
tail -f /var/log/syslog | grep disk_monitor
```

*Пример вывода:*

```text
disk_monitor[542]: [CREATED] File: /tmp/test_monitor_dir/hello.txt
disk_monitor[542]: [MODIFIED] File: /tmp/test_monitor_dir/hello.txt
disk_monitor[542]: [DELETED] File: /tmp/test_monitor_dir/hello.txt

```

### 4. Остановка демона

Демон перехватывает сигнал `SIGTERM` для корректного освобождения ресурсов (закрытие дескрипторов `inotify` и логов) перед выходом.

```bash
kill -TERM $(cat /tmp/disk_monitor.pid)
```

## Интеграция с systemd (Deploy)

При выполнении сборки CMake автоматически генерирует готовый юнит-файл для `systemd` на основе шаблона `deployments/systemd/disk-monitor.service.in`.
Сгенерированный файл (`out/disk-monitor.service`) содержит абсолютные пути к скомпилированному бинарнику и конфигурационному файлу, что позволяет сразу добавить демона в автозагрузку системы:

```bash
sudo cp out/disk-monitor.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl start disk-monitor
sudo systemctl enable disk-monitor
```
