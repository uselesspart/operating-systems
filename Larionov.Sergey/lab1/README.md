# Лабораторная работа №1 — Disk monitor

Автор: Ларионов Сергей. Вариант **20**, 15 баллов.

Программа на C++17 наблюдает за файлами в указанных каталогах через Linux
`inotify`. Каждое полученное уведомление записывается через `syslog` с facility
`LOG_LOCAL0`. Правило rsyslog направляет сообщения в `/var/log/diskmon.log`.
Наблюдение событийное: периодический интервал для варианта 20 не нужен.

## Сборка и быстрый запуск

Нужны Linux с `/proc`, Bash и `g++` с поддержкой C++17. Для тестов нужен Python 3.8+.
Внешних библиотек C++ нет. Команды выполняются из `Larionov.Sergey/lab1`.

```bash
./build.sh
mkdir -p demo/watched demo/second
./diskmon --check config.example
./diskmon config.example
```

Скрипт собирает один бинарник `diskmon` с `-std=c++17 -Wall -Wextra -Werror`.
Временный каталог сборки удаляется и при успехе, и при ошибке. Готовый бинарник
заменяется переименованием, поэтому разрешена сборка при работающем демоне.
Другой компилятор можно указать через `CXX=clang++ ./build.sh`.

Успешный запуск печатает `OK pid=...` **после** установки наблюдателей и записи
PID. Если демон не смог запуститься, команда возвращает ненулевой код и причину.

## Конфигурация

Одна строка — один существующий каталог. Пустые строки и строки, начинающиеся
с `#`, пропускаются. Пробелы внутри имени сохраняются: кавычки не нужны.

```text
# Пути относительно каталога конфигурационного файла
demo/watched
demo/second
/home/user/folder with spaces
```

Абсолютный путь **к самому конфигу** сохраняется до демонизации и `chdir("/")`.
Относительные пути каталогов при каждом чтении считаются от каталога конфига.
Повторяющиеся и вложенные корни объединяются, чтобы не дублировать события.
Конфиг с отсутствующим каталогом или без каталогов отклоняется целиком.

Каталоги наблюдаются рекурсивно, включая появившиеся и перемещённые внутрь
деревья. Символические ссылки внутри деревьев не обходятся. При переименовании
подкаталога обновляются пути всех его наблюдателей; пары перемещений связываются
через `cookie`. При выносе дерева за пределы наблюдения его наблюдатели снимаются.

## Управление

По умолчанию PID-файл: `/tmp/diskmon-$(id -u)/diskmon.pid`, в каталоге с правами
`0700`. Можно явно указать другой путь вторым аргументом:

```bash
./diskmon config.example /tmp/my-diskmon.pid
kill -HUP "$(cat /tmp/my-diskmon.pid)"
kill -TERM "$(cat /tmp/my-diskmon.pid)"
```

`SIGHUP` строит новый набор наблюдателей и заменяет старый только при успехе.
Ошибка даёт запись `RELOAD_FAILED`, прежние настройки продолжают работать.
`SIGTERM` (также `SIGINT`) записывает `STOP`, освобождает ресурсы и завершает процесс.

Повторный запуск с тем же PID-файлом проверяет старый PID через `/proc`,
отправляет прежнему экземпляру `SIGTERM`, ждёт освобождения блокировки и пишет
новый PID. Для чужого процесса сигнал не отправляется: проверяются владелец и
путь `/proc/PID/exe`. Проверка поддерживает пересборку работающего бинарника.
`flock` защищает PID-файл; соседний файл `.lock` сериализует одновременные запуски.

После нормального завершения PID-файл остаётся **пустым**, а `.lock` остаётся
существовать. Это сохраняет inode блокировки и исключает гонку с удалением файла.
После `SIGKILL` неактуальный PID заменяется при следующем запуске. Файлы с
некорректным PID, небезопасными правами и символьные ссылки отклоняются.

## Отдельный системный журнал

На Ubuntu/Debian с установленным rsyslog:

```bash
sudo install -m 0644 rsyslog/30-diskmon.conf /etc/rsyslog.d/30-diskmon.conf
sudo rsyslogd -N1
sudo systemctl restart rsyslog
sudo tail -f /var/log/diskmon.log
```

В системах с journald сообщения также доступны через:

```bash
journalctl -t diskmon --since '10 minutes ago' --no-pager
journalctl -t diskmon SYSLOG_FACILITY=16 --no-pager
```

Значение facility `16` соответствует `LOG_LOCAL0`. Демон использует `openlog`,
`syslog`, `closelog`; сам файл `/var/log/diskmon.log` создаёт rsyslog.
Файл журнала должен быть **вне наблюдаемых деревьев**, иначе запись в журнал
сама создаёт новые события.

Формат записи:

```text
diskmon[694]: event=MOVED_FROM path="/tmp/example/proof.txt" kind=file cookie=1991
diskmon[694]: event=MOVED_TO path="/tmp/example/renamed.txt" kind=file cookie=1991
```

Записываются `CREATE`, `OPEN`, `ACCESS`, `MODIFY`, `ATTRIB`, `CLOSE_WRITE`,
`CLOSE_NOWRITE`, `MOVED_FROM`, `MOVED_TO`, `DELETE`, `DELETE_SELF`, `MOVE_SELF`,
`UNMOUNT`. Имена с управляющими символами экранируются. Открытие, чтение и закрытие
самих **каталогов** не журналируются, чтобы обход дерева не создавал собственные
записи. Все перечисленные операции над обычными файлами журналируются.

## Проверки

```bash
./run_tests.sh
```

Выполняются отдельная C++-проверка singleton и **23 интеграционных сценария**:
контекст демона, операции над файлами, рекурсия, создание и перенос каталогов,
переименование, выход дерева из области наблюдения, пробелы и Unicode, symlink,
валидный и ошибочный `SIGHUP`, отсутствие утечек дескрипторов, повторный и
одновременный запуск, пересборка, очистка после ошибки сборки, `SIGKILL`,
посторонний и некорректный PID, защита PID-файла, удаление корня и восстановление
после его переноса, экранирование имён, проверка конфига.

Тесты создают реальные процессы, используют настоящий `inotify`, сигналы и
`/proc`. Вспомогательная `LD_PRELOAD`-библиотека перехватывает только вызовы
логирования, сохраняет проверяемую копию и передаёт сообщение настоящему syslog.
Она также поддерживает fortified-вызов `__syslog_chk`. Root для этих тестов не нужен.

Независимая демонстрация **без LD_PRELOAD**, через настоящие libc syslog,
journald и rsyslog (после установки правила выше):

```bash
sudo python3 tests/demo_syslog.py
```

Она проверяет отдельный log-файл, все основные операции, `SIGHUP`, отказ
ошибочного конфига, замену процесса и `SIGTERM`; дополнительно читает JSON journal
и проверяет `SYSLOG_FACILITY=16`. Временные каталоги и процессы убираются.

Результаты выполненного прогона: [отчёт](verification/README.md),
[23 теста](verification/tests.txt), [настоящий syslog](verification/syslog-demo.txt).

## Границы inotify

`inotify` объединяет одинаковые ещё не прочитанные уведомления, поэтому журнал
не является точным счётчиком системных вызовов. Механизм не гарантирует события
для `mmap`, удалённых изменений сетевых ФС и Windows-приложений, меняющих файлы
через `/mnt/c` в WSL. Для демонстрации используются каталоги в Linux `/tmp`.

При появлении нового каталога есть промежуток до установки его наблюдателя.
После удаления или переноса самого корня нужно обновить конфиг и отправить
`SIGHUP`. При `IN_Q_OVERFLOW` демон пишет ошибку и завершается с кодом 1:
потерянные события нельзя восстановить. Недоступные новые подкаталоги дают ошибку
в syslog; повторная установка наблюдения выполняется по `SIGHUP`.

Документация API: [inotify(7)](https://man7.org/linux/man-pages/man7/inotify.7.html),
[syslog(3)](https://man7.org/linux/man-pages/man3/syslog.3.html).
