# Лабораторная работа 1 — вариант 20

Linux-демон на C++. Конфигурация содержит произвольное число каталогов `dir <путь>`.

Демон через `inotify` отслеживает каждое обращение к файлам в этих каталогах и записывает его в журнал с facility `LOG_LOCAL0` (отдельный файл `/var/log/diskmon.log`).

## Реализовано

- демонизация через `fork()` + `setsid()` (родитель завершается, `chdir("/")`, дескрипторы 0/1/2 → `/dev/null`);
- singleton-класс `Daemon`;
- абсолютный путь к конфигу сохраняется до `chdir("/")`;
- каталоги задаются в конфиге (`dir <путь>`), их число произвольное, наблюдение через `inotify`;
- события `ACCESS`, `MODIFY`, `ATTRIB`, `OPEN`, `CLOSE_*`, `CREATE`, `DELETE`, `MOVED_*` пишутся в syslog через `LOG_LOCAL0`;
- `SIGHUP` перечитывает конфигурацию без перезапуска (при ошибке остаются прежние каталоги);
- `SIGTERM` пишет сообщение в syslog, удаляет pid-файл и корректно завершает демон;
- логирование через `openlog`, `syslog`, `closelog`;
- pid-файл `/var/run/diskmon.pid` (второй аргумент командной строки меняет путь);
- повторный запуск проверяет старый PID через `/proc`, отправляет старому процессу `SIGTERM`, ждёт завершения и затем записывает новый PID;
- сборка через `build.sh` с `-Wall -Werror`, промежуточные файлы удаляются;
- 28 автоматических тестов (юнит и интеграционные).

## Конфигурация

Пример `diskmon.conf`:

```text
dir /home/user/watch1
dir /home/user/watch2
```

Пути только абсолютные, строки с `#` и пустые строки игнорируются. Каталоги должны существовать.

Отдельный log-файл для `LOG_LOCAL0`:

```bash
sudo cp 10-diskmon.conf /etc/rsyslog.d/
sudo systemctl restart rsyslog
```

## Запуск

```bash
./diskmon diskmon.conf /tmp/diskmon.pid     
sudo ./diskmon diskmon.conf              
```

Перечитать конфиг:

```bash
kill -HUP $(cat /tmp/diskmon.pid)
```

Завершить:

```bash
kill -TERM $(cat /tmp/diskmon.pid)
```

Журналы:

```bash
sudo tail -F /var/log/diskmon.log          
journalctl -t diskmon -n 20 --no-pager     
```

Тесты автоматически проверяют (28 штук):

1. разбор конфига: комментарии, пробелы, относительные пути, дубликаты, неизвестные директивы;
2. формат событий `inotify`;
3. pid-файл: чтение и запись, проверка процесса через `/proc`, завершение предыдущего экземпляра;
4. реальный `inotify`: создание, изменение, чтение, переименование, удаление, несуществующий каталог;
5. запуск демона и создание pid-файла, события `LOG_LOCAL0` в журнале;
6. перечитывание конфига по `SIGHUP`, в том числе при пропавшем файле;
7. замену старого экземпляра при повторном запуске;
8. завершение по `SIGTERM` и удаление pid-файла, отсутствие терминала и новую сессию.

Тесты запускают демона с временным pid-файлом и подменой журнала (запись в файл), не мешают обычному экземпляру и не требуют настроенного rsyslog.
