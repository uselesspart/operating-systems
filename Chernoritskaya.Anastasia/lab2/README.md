# Лабораторная работа № 2. Межпроцессное взаимодействие. Вариант 16

## Вариант 16: 
Локальный сетевой чат, независимые процессы (один хост и один клиент), типы взаимодействия `mq` (POSIX очереди сообщений), `fifo` (именованные каналы) и `sock` (сокеты Unix-домена). Язык C++17, графический интерфейс хоста — Qt Widgets (Qt5 или Qt6), целевая система — Linux.

## Быстрый запуск в Linux

Зависимости Ubuntu:

```bash
sudo apt-get update
sudo apt-get install build-essential cmake qtbase5-dev libgtest-dev
```

*(Если у вас Qt6, замените `qtbase5-dev` на `qt6-base-dev`)*.

В каталоге работы:

```bash
make          # сборка всех host_* и client_*
make test     # сборка и запуск юнит-тестов
```

`make` вызывает `build.sh`, который очищает старые артефакты, собирает проект через CMake и копирует бинарники (`host_mq`, `host_fifo`, `host_sock`, `client_mq`, `client_fifo`, `client_sock`) в корень папки `lab2`. `make test` вызывает `run_tests.sh`, который запускает тесты.

`make clean` удаляет все бинарники, папку `build` и временные файлы IPC (`/tmp/my_*.sock`, `/tmp/my_*.fifo`).


## Три способа связи (Вариант 16)

| Программа | Реализация | Момент создания |
| :--- | :--- | :--- |
| **host_mq / client_mq** | POSIX очереди сообщений (`mq_open`) | Создаются хостом до запуска клиента. Клиент подключается к очереди по имени. |
| **host_fifo / client_fifo** | Именованные каналы (`mkfifo`) | Создаются хостом при запуске (`/tmp/my_c2s` и `/tmp/my_s2c`). Удаляются при завершении. |
| **host_sock / client_sock** | Сокеты Unix-домена (`AF_UNIX`) | Хост создает сокет и слушает его, клиент подключается. Хост получает PID клиента через `SO_PEERCRED`. |

Во всех случаях используются **глобальные семафоры** (`sem_open`), так как процессы независимые.

Каждое ожидание семафора ограничено **5 секундами**. При превышении таймаута связь прерывается, и клиент завершает работу. Для сокетов и FIFO используется неблокирующий `poll` с таймаутом 100 мс, чтобы не блокировать главный поток Qt (Event Loop). 

## Тесты

`make test` запускает 11 тестов на базе GoogleTest:
1. AddRemove — добавление и удаление участника.
2. BroadcastExcludesSender — широковещательная рассылка не отправляется отправителю.
3. PrivateValid — личное сообщение доходит до существующего получателя.
4. PrivateUnknown — личное сообщение для несуществующего получателя игнорируется.
5. Timeout60s — через 60 секунд бездействия клиент помечается как «просроченный».
6. HostNeverTimesOut — хост не удаляется (даже через 1000 секунд).
7. RemoveNonExistent — удаление несуществующего участника не ломает список.
8. AddDuplicateIgnored — повторное добавление участника не создает дубликат.
9. PrivateToSelf — личное сообщение самому себе доставляется.
10. MultipleTimeouts — одновременный таймаут двух участников; удаление одного не влияет на другого.
11. BroadcastEmptyChat — если в чате только хост, рассылка возвращает пустой список.
