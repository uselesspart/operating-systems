# Disk monitor — лабораторная 1, вариант 20

Программа работает в Linux. Она следит за путями из конфига через `inotify` и
отправляет события в syslog с facility `LOG_LOCAL0`.

## Сборка и запуск

```sh
./build.sh
./disk-monitor --config ./disk-monitor.conf
```

После `fork()` команда сразу завершается. Ошибки дальнейшего запуска дочернего
процесса записываются в syslog.

Для проверки на Linux остановите уже работающий экземпляр и запустите
`./tests/check.sh`. Скрипт собирает программу и проверяет события, `SIGHUP`,
повторный запуск и `SIGTERM`. По умолчанию он читает сообщения через `journalctl`.
Если события пишутся в отдельный читаемый файл, укажите его:

```sh
LOG_FILE=/var/log/disk-monitor.log ./tests/check.sh
```

Конфиг содержит одну строку вида `files = path1,path2,path3`. Пути могут быть
абсолютными. Относительные пути отсчитываются от каталога, из которого запущена
программа; это правило сохраняется и после перехода демона в `/`.
Указанные файлы или каталоги должны существовать к моменту запуска.

Демон записывает PID в `/tmp/disk-monitor-<uid>.pid`. Для перечитывания конфига
отправьте `SIGHUP`, для завершения — `SIGTERM`:

```sh
kill -HUP "$(cat /tmp/disk-monitor-$(id -u).pid)"
kill -TERM "$(cat /tmp/disk-monitor-$(id -u).pid)"
```

Повторный запуск прочитает PID из файла, проверит `/proc/<pid>` и отправит
предыдущему процессу `SIGTERM` перед запуском нового демона.
Если новый конфиг не удалось загрузить по `SIGHUP`, старые наблюдения сохраняются.

Чтобы направлять `LOG_LOCAL0` в отдельный файл, установите правило из
`rsyslog/30-disk-monitor.conf` в `/etc/rsyslog.d/` и перезапустите rsyslog.
