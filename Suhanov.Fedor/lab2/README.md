# PolyNet — лабораторная работа № 2, вариант 20

Локальный чат для Linux: один хост и несколько независимо запущенных клиентов.
Хост и клиенты работают в графическом интерфейсе Qt. Реализованы два транспорта:
Unix domain sockets (`sock`) и именованные каналы (`fifo`).

## Сборка

Требуются Linux ≥ 5.3, компилятор с поддержкой C++20, CMake ≥ 3.24, Make
и Qt 6 или Qt 5 Widgets. Пример установки зависимостей в Debian 12 / Ubuntu 24.04:

```sh
sudo apt-get install build-essential cmake qt6-base-dev
make
```

Собираются четыре приложения:

- `build/bin/host_sock`
- `build/bin/client_sock`
- `build/bin/host_fifo`
- `build/bin/client_fifo`

`make` вызывает `build.sh`, который очищает промежуточные файлы CMake
через `cmake --fresh` и выполняет сборку с `-Wall -Wextra -Werror`.
Новые исходники в `src` включаются в сборку автоматически. Для каждого нового
`src/conn_<код>.cpp` автоматически создаются `host_<код>` и `client_<код>`.
Функции `main` находятся в `src/host.cpp` и `src/client.cpp`.

Если Qt установлен в нестандартный каталог:

```sh
make CMAKE_ARGS=-DCMAKE_PREFIX_PATH=/путь/к/Qt
```

## Запуск

Сначала запустите хост:

```sh
./build/bin/host_sock --name host
```

PID хоста указан в заголовке окна и строке статуса. Затем запустите клиентов
в отдельных процессах, подставив этот PID:

```sh
./build/bin/client_sock --host 12345 --name alice
./build/bin/client_sock --host 12345 --name bob
```

Для FIFO замените `sock` на `fifo` в именах обеих программ. Хост и клиенты
должны использовать один транспорт и работать под одним пользователем.
Хост создаёт ресурсы связи и не запускает клиентов через `fork()`.

В окне выберите «Всем участникам» или конкретного адресата, введите текст
и нажмите Enter либо «Отправить». Личное сообщение видно только отправителю
и адресату. Хост может отправлять общие и личные сообщения.

Имена уникальны, занимают 1–32 байта UTF-8 и не содержат пробелов; сообщения
занимают 1–2048 байт UTF-8. Управляющие символы запрещены.

История отображает сообщения, подключения, отключения, запуск и ошибки.
Операции связи выполняются в фоновых потоках. Ошибки также записываются
в stderr. Закрытие окна завершает соединение и освобождает ресурсы.
Клиенты завершаются при остановке хоста или разрыве связи.

Горячие клавиши:

| Клавиши | Действие |
| --- | --- |
| Enter в поле сообщения | Отправить сообщение |
| Alt+M | Перейти к полю сообщения |
| Alt+R | Выбрать адресата |
| Alt+H | Перейти к истории |
| Ctrl+Q | Закрыть окно |

Если клиент не отправляет сообщений больше 60 секунд, хост завершает его
сигналом `SIGKILL`. Входящие сообщения этот срок не продлевают. Хосту
разрешено бездействовать неограниченное время.

## Проверки

Для автоматических проверок графического интерфейса установите:

```sh
sudo apt-get install python3 xvfb xauth xdotool xclip
make test
make test-idle
```

`make test` запускает для каждого транспорта хост и три клиента с настоящими
Qt-окнами в виртуальном X-дисплее. Проверяются одновременное знакомство,
общий и личный чат, сообщения хоста и самому себе, порядок сообщений,
UTF-8 и максимальный размер, дубликат имени, отсутствие хоста,
пятисекундные тайм-ауты, отключение зависшего получателя и очистка ресурсов.
Управление выполняется через клавиатуру и буфер обмена графического интерфейса.

`make test-idle` дополнительно проверяет настоящий минутный интервал
бездействия при продолжающемся получении чужих сообщений. Эта проверка
занимает несколько минут для обоих транспортов.

## Протокол и ресурсы

Каждого клиента обслуживает отдельный поток. Знакомство использует
`SIGUSR1`/`SIGUSR2`, синхронизация чтения и записи — именованные семафоры
`sem_open` с тайм-аутом 5 секунд. Порядок сообщений и время их фиксации
назначает единый диспетчер хоста.

Ресурсы хоста находятся в `/tmp/polynet_<uid>_<код>_<PID>`, семафоры имеют
префикс `/pn<код>_<PID>_`. При штатном завершении и обработанном SIGINT/SIGTERM
ресурсы удаляются. Принудительный SIGKILL самому хосту не позволяет выполнить
очистку: его оставшиеся ресурсы удаляются вручную после завершения процесса.

Формат пакетов, порядок сообщений и синхронизация описаны
в [docs/protocol.md](docs/protocol.md).
