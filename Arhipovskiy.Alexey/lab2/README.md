# Лабораторная работа №2. Локальный сетевой чат (вариант 20)

Сценарий 2, конфигурация «Независимые. Один ко многим», типы взаимодействия:
программные каналы (`pipe`), именованные каналы (`fifo`), сокеты (`sock`).

Хост является участником чата с графическим интерфейсом на Qt. Клиенты являются консольными
программами и запускаются независимо, им передаётся pid хоста. Хост пишет общие и личные
сообщения и пересылает сообщения клиентов: общие видят все, личные только отправитель и
адресат. Клиент, который не пишет дольше минуты, получает SIGKILL. Сообщения показываются в
порядке времени отправки.

## Как это работает

| Что | Как сделано |
|---|---|
| знакомство | клиент шлёт SIGUSR1 на pid хоста; хост создаёт канал и семафоры для нового клиента и отвечает `sigqueue(SIGUSR1)` с номером клиента. Обычные сигналы не копятся, поэтому клиент повторяет запрос раз в секунду, хост на повтор отвечает тем же номером |
| синхронизация | два глобальных семафора на клиента (`sem_open`, `/chat_<pid хоста>_<номер>_up` и `_down`): отправитель пишет кадр целиком и делает `sem_post`, получатель ждёт `sem_timedwait` |
| тайм-ауты | любое ожидание семафора, сигнала или подключения длится не больше 5 с, после этого связь разрывается, клиент завершается с кодом 1 |
| потоки | у хоста отдельный поток на каждого клиента и поток приёма сигналов, окно Qt работает в главном потоке |
| обмен | клиент раз в 200 мс отправляет запрос со своими новыми сообщениями, хост отвечает сообщениями для этого клиента, уведомлениями и списком участников |
| порядок | у сообщения есть время отправки; хост отдаёт сообщения не раньше чем через 400 мс, отсортированными по этому времени, поэтому сообщения от медленного клиента не обгоняются |
| молчание | клиент без сообщений дольше 60 с получает SIGKILL, остальные видят причину ухода |
| журнал | ошибки и события пишутся в syslog (`chat_host`, `chat_client`), хост дублирует их в stderr, окно хоста показывает подключения и отключения |

| Тип | Канал между хостом и клиентом N |
|---|---|
| `pipe` | хост создаёт два `pipe` и держит концы клиента на дескрипторах `1000 + 2N` и `1001 + 2N`; клиент, как независимый процесс, открывает их через `/proc/<pid хоста>/fd/` |
| `fifo` | `/tmp/chat_<pid хоста>/fifo_N_up` и `fifo_N_down`, хост удаляет их по окончании работы |
| `sock` | Unix-сокет `/tmp/chat_<pid хоста>/sock_N` |

## Установка и сборка

Нужны:

- CMake 3.16 и новее, make
- компилятор C++17: GCC 9 и новее или Clang
- Qt 6 или Qt 5.15 с модулем Widgets (для тестов ещё модуль Test)
- bash, только для тестов
- 
Затем устнавливаются пакеты для выбранного диструбутива:

| Дистрибутив | Пакеты |
|---|---|
| Ubuntu, Debian | `sudo apt install cmake make g++ qt6-base-dev` |
| Fedora, RHEL, Rocky | `sudo dnf install cmake make gcc-c++ qt6-qtbase-devel` |
| Arch, Manjaro | `sudo pacman -S cmake make gcc qt6-base` |
| openSUSE | `sudo zypper install cmake make gcc-c++ qt6-widgets-devel qt6-test-devel` |

Где Qt 6 нет, подойдёт Qt 5: `qtbase5-dev` (Debian, Ubuntu), `qt5-qtbase-devel` (Fedora, RHEL),
`qt5-base` (Arch). CMake сам выберет найденную версию. Для просмотра окна через VNC в Debian и
Ubuntu нужен ещё пакет `qt6-qpa-plugins`.

А после запускается:

```sh
make            # host_pipe host_fifo host_sock client_pipe client_fifo client_sock
make clean      # delete assembled solution
```

## Запуск

Хост и клиенты должны быть одного типа связи. Сначала хост:

```sh
./host_sock
```

Pid хоста виден в заголовке окна, в строке состояния и в журнале. Клиенты в других терминалах
(в том числе по ssh):

```sh
./client_sock <pid_host> Алиса
./client_sock <pid_host> Борис
```

Если имя не указано, клиент получает имя «Клиент N». В окне хоста сообщение пишется в нижней
строке, адресат выбирается слева от неё: «Всем» или конкретный участник.

| Команда клиента | Что делает |
|---|---|
| `текст` | сообщение всем |
| `/to N текст` или `@N текст` | личное сообщение участнику N, хост имеет номер 0 |
| `/who` | список участников |
| `/help` | список команд |
| `/quit`, Ctrl+C, Ctrl+D | выйти из чата |

Строку клиента редактирует сам терминал: Backspace работает и для русских букв (клиент включает
терминалу режим UTF-8), стрелки и история команд не поддерживаются, их коды отбрасываются. Кроме
того, хост убирает из любых сообщений управляющие последовательности и испорченный UTF-8.

Хост завершается закрытием окна, Ctrl+C в его терминале или `kill -TERM <pid>`: клиенты
получают «Чат закрыт: хост завершает работу». Если хост убит SIGKILL, клиенты замечают это
примерно через 5 с, а следующий запуск хоста удаляет оставшиеся файлы и семафоры.

## Окно хоста на сервере без экрана

Любой из способов:

| Способ | Как |
|---|---|
| VNC | на сервере `QT_QPA_PLATFORM=vnc:size=960x600 ./host_sock` (порт 5900), на Windows VNC-клиент (TightVNC, RealVNC) на `<ip сервера>:5900`; безопаснее через туннель `ssh -L 5900:localhost:5900 user@server` и `localhost:5900` |
| X11 по ssh | MobaXterm (в нём есть X-сервер) или `ssh -X user@server`, затем `./host_sock`; на сервере нужен пакет `xauth` |
| WSL | на Windows 11 в WSL с Ubuntu окно открывается прямо в Windows |
| без окна | `QT_QPA_PLATFORM=offscreen ./host_sock`: окна нет, все события видны в stderr и журнале |

## Журналы

| Что | Где |
|---|---|
| хост | stderr хоста, `journalctl -t chat_host -f` или `grep chat_host /var/log/syslog` |
| клиенты | `journalctl -t chat_client` |

Для проверки отключения молчащих клиентов без минутного ожидания предел можно уменьшить:
`CHAT_IDLE_LIMIT_SEC=10 ./host_sock`.
