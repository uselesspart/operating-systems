## Задание

В конфигурационный файл пользователь добавляет события с помощью скрипта
`add_event date time [flag] text`. Флаги `-h`, `-d`, `-w` задают повтор
каждый час, день или неделю. В указанное время демон открывает новый терминал
и выводит текст напоминания. Интервал проверки — 10 секунд.

## Сборка

```sh
./build.sh        # собирает ./reminderd
./build.sh test   # собирает и запускает тесты (criterion)
```

Сборка идёт через cmake во временном каталоге, который удаляется после завершения.
Флаги компиляции: `-Wall -Werror`.

Если criterion не установлен в системе (не находится через pkg-config),
cmake сам скачивает готовую сборку criterion 2.4.2 с GitHub.

## Запуск

```sh
./reminderd [config]
```

По умолчанию используется `reminder.conf` из текущего каталога. Путь к
конфигу запоминается как абсолютный, после чего процесс уходит в фон.

PID записывается в `/tmp/reminderd.pid`. Если при запуске там лежит pid живого
процесса (проверка через `/proc`), ему отправляется `SIGTERM`, и только потом
новый демон занимает его место.

Сигналы:

- `SIGHUP` — перечитать конфиг;
- `SIGTERM` — записать сообщение в журнал и завершиться.

Журнал:

```sh
journalctl -t reminderd -f
```

## Конфигурационный файл

```
interval 10
terminal xterm

2026-10-26 09:00 -d Check mail
2026-10-27 18:30 -w Operating systems lab
2026-10-28 12:00:30 Call mom
```

- `interval N` — период проверки в секундах (по умолчанию 10);
- `terminal NAME` — эмулятор терминала. Если не указан или не запускается,
  перебираются `x-terminal-emulator`, `xterm`, `konsole`, `gnome-terminal`, `kitty`;
- остальные строки — события `YYYY-MM-DD HH:MM[:SS] [-h|-d|-w] текст`;
- строки, начинающиеся с `#`, игнорируются; некорректные строки пропускаются
  с предупреждением в журнале.

## Добавление событий

```sh
./add_event.sh 2026-10-25 21:00 "Lab deadline tomorrow"
./add_event.sh 2026-10-26 08:00 -d Take vitamins
./add_event.sh -c /path/to/other.conf 2026-10-26 10:00 -h Stretch
```

Скрипт проверяет дату, дописывает строку в конфиг и отправляет демону `SIGHUP`.
Разовое событие в прошлом добавить нельзя.

## Как срабатывают события

Демон запоминает время последней проверки и на каждой итерации ищет события,
которые попадают в промежуток `(последняя проверка, сейчас]`. Для повторяющихся
событий берётся ближайшее повторение. Поэтому после `SIGHUP` старые события
повторно не показываются, а пропущенные во время работы не теряются.
