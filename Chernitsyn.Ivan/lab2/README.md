# Лабораторная работа № 2. Межпроцессное взаимодействие

Черницын Иван, вариант 5. Хост играет за волка, один независимый клиент — за козлёнка. Для каждой пары программ используется свой канал.

| Суффикс | Канал |
| --- | --- |
| seg | Сегмент общей памяти System V, создаваемый через shmget |
| mq | Очередь сообщений POSIX, создаваемая через mq_open |
| fifo | Именованный канал, создаваемый через mkfifo |

## Сборка и проверка

Нужны Linux, компилятор C++17, CMake 3.24 или новее, make, pkg-config и пакет разработки Qt Widgets 5 или 6. В каталоге лабораторной выполните:

```sh
make
make test
```

Обе команды собирают программы в каталоге `bin`. Команда `make test` также запускает тесты Criterion. CMake ищет Criterion через pkg-config. Если библиотека отсутствует, на Linux x86-64 CMake скачивает официальный архив версии 2.4.2 и проверяет его контрольную сумму. На других архитектурах нужен системный пакет разработки Criterion.

## Запуск

Запустите хост, например для очереди сообщений:

```sh
./bin/host_mq
```

Хост выведет свой PID в терминал и в заголовок окна. В другом терминале запустите клиент той же пары, подставив этот PID вместо 12345:

```sh
./bin/client_mq 12345
```

Клиент сообщает о подключении сигналом SIGUSR1. Два именованных семафора задают очередь записи и чтения, ещё один резервирует место единственного клиента. При отсутствии ответа в течение пяти секунд клиент завершает работу.

На каждом ходу введите число от 1 до 100 и нажмите Enter или кнопку «Сделать ход». Через три секунды хост сам бросает число. Живой козлёнок бросает число от 1 до 100 и прячется при разнице не более 70. Мёртвый бросает от 1 до 50 и воскресает при разнице не более 20. Игра заканчивается после двух ходов подряд, на которых козлёнок остался мёртв. Журнал ходов остаётся в окне до его закрытия.
