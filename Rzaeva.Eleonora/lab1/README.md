# Лабораторная работа 1. Демон-очистка каталогов (вариант 14)

Демон на C++ (`fork`, демонизация) периодически, через заданный интервал, проходит
по каталогам из конфигурационного файла и **удаляет содержимое каталога `folder`,
если в нём отсутствует файл-«защита» `ignfile`**; если файл есть - не делает ничего.

Общие требования задания также выполнены:

- запуск, ошибки, перечитывание конфига, очистки и завершение пишутся в системный
  журнал через `openlog`/`syslog`/`closelog`;
- по `SIGHUP` конфиг перечитывается, по `SIGTERM` демон пишет сообщение о выходе и
  завершается;
- защита от повторного запуска через pid-файл: старый процесс ищется по `/proc`,
  ему отправляется `SIGTERM`, а свой pid записывается уже **после** демонизации;
- класс демона - синглтон;
- сборка скриптом `build.sh` с флагами `-Wall -Werror` в один исполняемый файл,
  промежуточные файлы удаляются.

Только Linux: используются `/proc`, `sigtimedwait`, systemd-журнал.

## Сборка

```bash
./build.sh          # результат: ./daemon
```

## Запуск и управление

```bash
./daemon [путь_к_конфигу]        # без аргумента берётся ./daemon.conf

kill -HUP  "$(cat /tmp/rzaeva_dir_cleaner.pid)"   # перечитать конфиг
kill -TERM "$(cat /tmp/rzaeva_dir_cleaner.pid)"   # завершить
```

Путь к pid-файлу по умолчанию `/tmp/rzaeva_dir_cleaner.pid`, его можно переопределить
переменной окружения `RZAEVA_PID_FILE` (используется тестами).

Просмотр журнала:

```bash
journalctl -t rzaeva_dir_cleaner -f
```

Быстрая демонстрация: `./demo.sh` - сам создаёт каталоги в `/tmp/rzaeva_demo`,
запускает демон и показывает, что осталось после очистки.

## Конфигурационный файл

Произвольное число строк. Первой обычно идёт `interval N`; далее - строки
`folder ignfile`. Строки, начинающиеся с `#`, и пустые строки игнорируются.

```
interval 20
/tmp/rzaeva_demo/protected keep.txt
relative/dir .keep          # относительно каталога, где лежит конфиг
```

- `interval N` - период между проверками в секундах (по умолчанию 20);
- `folder` - каталог (абсолютный или относительный к каталогу конфига);
- `ignfile` - имя файла-«защиты» внутри `folder` (или абсолютный путь к нему).

Абсолютный путь к конфигу запоминается при запуске **до** смены рабочего каталога
на `/`, поэтому перечитывание по `SIGHUP` работает независимо от того, откуда был
запущен демон.

Битые строки и несуществующие каталоги не прерывают работу: о них пишется
предупреждение в журнал, строка пропускается.

## Тесты

```bash
./run_tests.sh                            # все тесты
./run_tests.sh -L unit                    # только unit-тесты
./run_tests.sh -L component               # только компонентные
./run_tests.sh --gtest_filter='*Sighup*'  # фильтр по именам gtest-кейсов
```

| Каталог | Что проверяется |
|---|---|
| `tests/ut/` | классы по отдельности: разбор конфига, проверка `ignfile` и очистка каталога, pid-файл и `/proc`, синглтон демона |
| `tests/ct/` | запуск готового бинарника демона: демонизация, действие над каталогами, сигналы `SIGHUP`/`SIGTERM`, pid-файл, сообщения в журнале |

Компонентные тесты читают системный журнал через `journalctl` по полю `_PID`
(pid демона). Поэтому для их запуска нужен работающий systemd-журнал; если
`journalctl` недоступен, компонентные тесты помечаются пропущенными, а unit-тесты
выполняются всегда.

Если системный GoogleTest не найден, CMake скачает его через `FetchContent`
(нужен доступ к сети на этапе конфигурации). Чтобы использовать системный GTest,
установите пакет `libgtest-dev`.

## Устройство

| Модуль | Назначение |
|---|---|
| `src/config.{hpp,cpp}` | разбор конфига, приведение относительных путей к абсолютным |
| `src/cleaner.{hpp,cpp}` | проверка файла-«защиты» и очистка содержимого каталога |
| `src/pid_manager.{hpp,cpp}` | pid-файл, проверка процесса через `/proc`, остановка старого экземпляра |
| `src/daemon.{hpp,cpp}` | синглтон демона: `fork`, `setsid`, `chdir("/")`, перенаправление дескрипторов, сигналы, главный цикл |
| `src/main.cpp` | точка входа |

Класс `Daemon` - синглтон, доступен через `Daemon::instance()`.

Первая проверка выполняется сразу после запуска, затем каждые `interval` секунд.
