# Лабораторная работа 1. Демон Dir cleaner (вариант 18)

Демон периодически, через заданный интервал, проверяет папки из конфигурационного файла.
Для каждой папки `folder` с заданной глубиной `depth` удаляются все её подпапки вплоть до этой глубины.
Всё, что лежит глубже (глубина > `depth`), сохраняется.
Запуск, ошибки, перечитывание конфига, удаления и завершение работы записываются в syslog
(`openlog`/`syslog`/`closelog`). Только Linux: используются `fork`, `/proc`, `signal`.

## Сборка

```bash
./build.sh            # результат: ./lab1_daemon, промежуточные файлы удаляются
```

## Тесты

```bash
./test.sh                 # запуск интеграционных тестов
```

## Конфигурация

Файл `config.txt` в рабочей папке (или путь первым аргументом: ./lab1_daemon /path/to/config.txt):

```text
interval 20
/home/bi/test_folder 2
```

- `interval N` - период между проверками в секундах (по умолчанию 20);
- `folder depth` - произвольное число строк. `folder` - папка, `depth` - максимальная глубина удаления подпапок;

Абсолютный путь к конфигу запоминается при запуске (до смены рабочей директории на `/`), поэтому перечитывание по `SIGHUP` работает независимо от того, откуда был запущен демон.

Особенность реализации логики удаления: чтобы удалить подпапки до depth, но оставить те, что глубже, программа сначала запоминает глубокие папки, затем очищает folder целиком, а потом восстанавливает глубокие папки заново (создавая для них пустые родительские папки-контейнеры, чтобы структура не ломалась).

## Запуск и управление

```bash
./lab1_daemon config.txt                          
kill -HUP  $(cat /tmp/lab1_daemon.pid)   # перечитать конфиг
kill -TERM $(cat /tmp/lab1_daemon.pid)   # завершить
```

Просмотр журнала:

```bash
journalctl -t lab1_daemon -f             # journald
grep lab1_daemon /var/log/syslog         # если используется rsyslog
```

Повторный запуск находит старый экземпляр по pid-файлу `/tmp/lab1_daemon.pid`, проверяет его наличие через `/proc/<pid>`, отправляет ему `SIGTERM`, дожидается завершения и после демонизации записывает свой pid.

## Устройство

Класс `Daemon` — синглтон (доступ через `Daemon::instance()`).

| Модуль | Назначение |
|---|---|
| `main.cpp` | весь исходный код (включая класс Daemon) |
| `build.sh` |   скрипт сборки с флагами -Wall -Werror, очистка .o |
| `test.sh` | интеграционные тесты (структура папок, сигналы, pid-файл) |

Внутри класса Daemon:
- защита от повторного запуска, работа с /proc и pid-файлом;
- разбор конфига и перечитывание по SIGHUP;
- логика рекурсивного удаления с сохранением глубоких уровней;
- главный цикл с ожиданием и обработкой SIGTERM.

Первая проверка выполняется сразу после запуска, затем каждые `interval` секунд.
