# Лабораторная работа 2: межпроцессное взаимодействие

Вариант 3. Сценарий "Волк и семеро козлят", родственные процессы, один к одному.
Реализованы очереди сообщений POSIX (`mq`), именованные каналы (`fifo`) и сокеты (`sock`).
Синхронизация выполнена локальными семафорами `sem_init` в разделяемой памяти.

## Требования

- Linux;
- компилятор с поддержкой C++17;
- CMake 3.16 или новее;
- GNU Make;
- Qt 6 или Qt 5 с модулем Widgets;
- графическая сессия (X11 или Wayland).

Установка зависимостей в Debian/Ubuntu:

```bash
sudo apt install build-essential cmake qt6-base-dev
```

Если используется Qt 5, достаточно пакета `qtbase5-dev`.

## Сборка

```bash
./build.sh
```

или

```bash
make
```

`build.sh` собирает проект во временном каталоге и удаляет все промежуточные файлы CMake.
Готовые программы `host_mq`, `host_fifo` и `host_sock` появляются в корне проекта.

## Запуск

```bash
./host_mq
./host_fifo
./host_sock
```

Хост создаёт дочерний процесс-козлёнка и открывает главное окно. Отдельный запуск клиента не нужен.
При закрытии окна, нажатии `Ctrl+C` или получении `SIGTERM` хост завершает козлёнка и удаляет очереди, файлы каналов и семафоры.
После `SIGKILL` очистку выполнить невозможно, поэтому в этом случае ресурсы с именами от старого процесса нужно удалить вручную.

## Правила игры

1. В начале раунда волк вводит число от 1 до 100 в поле окна и нажимает "Сделать ход" или Enter.
   Если за 3 секунды число не введено, оно выбирается случайно.
2. Живой козлёнок бросает число от 1 до 100, мёртвый от 1 до 50.
3. Живой козлёнок прячется, если разница между его числом и числом волка не больше 70/n, иначе он попадается и становится мёртвым.
   Мёртвый козлёнок воскресает, если разница не больше 20/n.
4. В варианте 3 количество козлят n равно 1, поэтому пороги равны 70 и 20. Границы включаются.
5. Игра заканчивается, если козлёнок мёртв два раунда подряд. Воскрешение сбрасывает счётчик мёртвых раундов.
6. Результат раунда выводится в журнал окна: числа волка и козлёнка, количество спрятавшихся, попавшихся и мёртвых козлят.
   В строке состояния отображается текущее состояние козлёнка, в отдельной строке общие счетчики.

## Устройство программы

- `fork` выполняется до создания `QApplication`, чтобы в дочернем процессе не было объектов Qt.
- Общие данные находятся в `mmap(MAP_SHARED | MAP_ANONYMOUS)`: семафоры `host_turn`, `client_turn`, `channel_ready`, имя канала и пара дескрипторов `socketpair`.
- Очереди сообщений и именованные каналы создаются уже после `fork`, как для несвязанных процессов. Для сокета используется `socketpair`, созданный до `fork`.
- Все ожидания семафоров, чтения и записи ограничены 5 секундами. При таймауте связь прерывается, клиент завершает работу, хост показывает ошибку.
- Обмен идет сообщениями фиксированного размера 16 байт: тип, номер раунда, значение, признак завершения игры.
- Игровая логика находится в хосте. Клиент бросает число и получает статус козлёнка.
- Клиент пишет сообщения в системный журнал с меткой `wolf_client`. Хост показывает статусные сообщения в окне.

## Тесты

```bash
make test
```

Тесты проверяют:

- правила игры, границы 70/71 и 20/21, завершение после двух мёртвых раундов, диапазоны чисел;
- для каждого транспорта обмен между процессами через `fork` и ограничение ожидания пятью секундами;
- работу окна хоста и игрового цикла без графической сессии (Qt работает в режиме offscreen);
- полный цикл хост-клиент через каждый транспорт до завершения игры.

После выполнения тестов каталог `build-tests` удаляется.
