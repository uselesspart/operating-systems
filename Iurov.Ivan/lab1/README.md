# TreeCleaner - лабораторная работа №1, вариант 18

Реализация на **C++17 для Linux**. Программа читает конфигурацию, где каждая непустая строка имеет формат:

```text
folder depth
```

Пример `config.example` приведён в корне проекта.

## Трактовка глубины

У `folder` глубина 0. Его непосредственные подкаталоги имеют глубину 1, их подкаталоги - глубину 2 и т. д. Программа удаляет каталоги **ровно на уровне `depth`**, включая содержимое этих каталогов. Сам исходный `folder` и каталоги выше целевого уровня сохраняются. Например, при глубине 2 каталоги первого уровня остаются, но их каталоги второго уровня удаляются вместе с содержимым.

Так как формулировка «вплоть до глубины» допускает неоднозначное толкование, перед сдачей стоит подтвердить эту трактовку у преподавателя.

## Безопасность

- Символические ссылки не обходятся и не считаются каталогами.
- Если сам исходный `folder` является символической ссылкой, операция запрещается.
- Удаление подкаталогов корня файловой системы `/` запрещено.
- Глубина должна быть в диапазоне `1..1024`; `0` запрещён, чтобы нельзя было удалить исходный каталог.
- Ошибка одного пути записывается в журнал; обработка остальных строк конфигурации продолжается.
- Конфигурация поддерживает пустые строки, комментарии с `#` и комментарии в конце строки. Пути с пробелами не поддерживаются, поскольку формат строки содержит два поля.
- Относительные пути в конфигурации разрешаются относительно каталога самого конфигурационного файла.

> Внимание: программа действительно удаляет каталоги. Для проверки сначала используйте `--once` и только временные тестовые каталоги.

## Сборка

Требуются Linux, CMake 3.16+, компилятор C++ с поддержкой C++17 и стандартные системные библиотеки.

```bash
./build.sh
```

Эквивалентная ручная сборка:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
```

## Тесты

```bash
./test.sh
```

Либо после сборки:

```bash
ctest --test-dir build --output-on-failure
```

Тесты создают отдельные временные каталоги и проверяют глубины 0, 1, 2 и недостижимую глубину, работу с конфигурацией и защиту от символических ссылок.

## Запуск

### Один проход (для ручной проверки)

```bash
./build/treecleaner --config ./config.example --once
```

`config.example` содержит путь-заготовку `./demo-data`; замените его на каталог, созданный специально для проверки, либо создайте этот каталог. Для полностью изолированной ручной проверки можно выполнить:

```bash
mkdir -p /tmp/treecleaner-demo/root/first/second
printf '/tmp/treecleaner-demo/root 2\n' > /tmp/treecleaner-demo/cleaner.conf
./build/treecleaner --config /tmp/treecleaner-demo/cleaner.conf --once
# Удалится root/first/second; root/first останется.
```

В режиме `--once` журнал выводится в `stderr`. Можно указать файл журнала:

```bash
./build/treecleaner --config ./config.example --once --log-file ./treecleaner.log
```

### Длительная работа в терминале

```bash
./build/treecleaner --config /absolute/path/cleaner.conf --foreground --interval 60
```

Программа сначала выполняет проход, затем повторяет его каждые 60 секунд. `SIGTERM`/`SIGINT` останавливают процесс, `SIGHUP` перечитывает конфигурацию. Если конфигурация при перечитывании некорректна, используется предыдущая корректная версия.

### Запуск демоном

```bash
./build/treecleaner --config /absolute/path/cleaner.conf --daemon --interval 60
```

По умолчанию журнал находится в `/tmp/treecleaner-<UID>.log`, PID-файл - в `/tmp/treecleaner-<UID>.pid`. Их можно переопределить параметрами `--log-file` и `--pid-file`.

Остановить демон:

```bash
kill -TERM "$(cat /tmp/treecleaner-$(id -u).pid)"
```

Перечитать конфигурацию:

```bash
kill -HUP "$(cat /tmp/treecleaner-$(id -u).pid)"
```

PID-файл блокируется через `flock`, поэтому второй экземпляр с тем же PID-файлом не запустится. При нормальной остановке PID-файл удаляется.

## Формат конфигурации

```text
# строки-комментарии игнорируются
./cache 1
./application-cache 2
```

Глубина должна быть целым числом от 1 до 1024. Путь должен указывать на существующий каталог, не являющийся символической ссылкой. Относительные пути отсчитываются от директории файла конфигурации, а не от текущей директории процесса.
