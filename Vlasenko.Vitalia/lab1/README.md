# Лабораторная №1 — создание демона в Linux (вариант 17)

Программа написана на **C++17** для Linux (проверяется с `g++`). При запуске как демон она рекурсивно обходит исходные каталоги, с заданным интервалом очищает каталоги назначения и копирует файлы по правилам конфигурации.

## Структура проекта

```text
include/         Заголовочные файлы C++
src/             Реализация (Config, FileSorter, Daemon, PidFile)
tests/           Автоматические тесты C++ и Bash
build.sh         Сборка приложения
test.sh          Сборка и запуск всех тестов
config.txt       Основная конфигурация (интервал 60 секунд)
test_data/source/     Пример исходного дерева
bin/             Создаваемые сборкой исполняемые файлы
run/             Служебные PID-файлы при работе демона
test_data/destination/  Выходные файлы сортировки
```

Пустые файлы в `test_data/source/` — **макеты для проверки имён и расширений**, а не настоящие картинки или PDF. Для демонстрации копирования содержимого можно заменить их реальными небольшими файлами.

## Сборка и тесты

```bash
cd ~/Projects/os_lab1
./build.sh
./test.sh
```

`build.sh` использует `-std=c++17 -Wall -Wextra -Werror`. Объектные файлы `.o` не создаются. `test.sh` самостоятельно вызывает `build.sh`, поэтому предварительная сборка для тестов необязательна. Тесты создают временные каталоги в `/tmp`, не очищая пользовательские каталоги `test_data`.

При необходимости разрешения можно восстановить командой:

```bash
chmod +x build.sh test.sh tests/*.sh
```

## Конфигурационный файл

Формат файла `config.txt`:

```ini
# Период в секундах
interval=60

# folder1 folder2 ext subfolder
test_data/source test_data/destination .png IMAGES
```

Каждая строка правила содержит **ровно 4 поля**: `folder1 folder2 ext subfolder`. Можно указать несколько строк правил; для каждого правила используется **одно** расширение. Пути могут быть абсолютными или относительными; относительные разрешаются от каталога самого конфига. Пробелы в путях этим форматом не поддерживаются.

При обработке каждого правила каталог `folder2` очищается, затем файлы с расширением `ext` попадают в `folder2/subfolder/`, остальные — в `folder2/OTHERS/`. Вложенные пути файлов сохраняются. Совпадение расширения учитывает регистр: `.png` и `.PNG` различаются. Символические ссылки пропускаются, а **пустые исходные каталоги не копируются**. Пересекающиеся каталоги назначения и пересечения назначения с любым источником запрещены: это защита от удаления исходных файлов и результатов других правил.

**Осторожно:** содержимое каждого `folder2` удаляется перед копированием. Используйте специальный каталог назначения, в котором нет ценных данных.

## Запуск демона

```bash
# Постоянная работа в фоне с PID-файлом:
./bin/sorter-test --daemon config.txt

# То же на переднем плане: удобно наблюдать сообщения об ошибках:
./bin/sorter-test --daemon config.txt --foreground
```

PID-файл находится в `run/sorter.pid` **рядом с конфигом** (в подкаталоге `run/`). Он содержит PID и время старта процесса из `/proc/<pid>/stat`. Файл `run/sorter.pid.lock` используется для блокировки `flock()`, его не нужно удалять вручную. Новый запуск с другим конфигом **из того же каталога** заменит предыдущий экземпляр, потому что PID-файл общий для каталога конфигурации.

Повторный запуск `--daemon` сверяет предыдущий PID с данными `/proc`, отправляет `SIGTERM` проверенному прежнему экземпляру, дожидается завершения и запускает новый.

```bash
# Узнать PID активного демона:
head -n 1 run/sorter.pid

# После редактирования config.txt перечитать конфигурацию:
kill -HUP "$(head -n 1 run/sorter.pid)"

# Корректно завершить демон и удалить его PID-файл:
kill -TERM "$(head -n 1 run/sorter.pid)"

# Системный журнал:
journalctl -t sorter-daemon -n 30 --no-pager
```

Если конфигурация при `SIGHUP` ошибочна, прежние корректные настройки сохраняются. Обработка ошибок и завершение по `SIGTERM` регистрируются через `syslog`.

### Известные ограничения

- Пустые каталоги источника не восстанавливаются в назначении — создаются пути для копируемых файлов.
- Если копирование оборвётся после очистки назначения, результат цикла может быть частичным. Транзакционное копирование через временный каталог не реализовано.
- Работа с PID-файлом защищает от обычного повторного использования PID, но не от намеренной подмены данных пользователем, способным изменять файлы проекта.
