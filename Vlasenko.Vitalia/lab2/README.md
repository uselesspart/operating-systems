# Лабораторная работа №2. Межпроцессное взаимодействие в Linux

## Задание

Вариант №10 — «Волк и семеро козлят». Независимые процессы, взаимодействие «один ко многим».

Хост — графическое приложение Qt, клиенты — консольные приложения. Для каждого клиента создаётся отдельный поток на стороне хоста. Знакомство процессов выполняется через сигналы `SIGUSR1` и `SIGUSR2`, синхронизация — через именованные POSIX-семафоры. Тайм-аут операций ожидания — 5 секунд, кроме запланированного ожидания.

Поддерживаются три механизма IPC: `pipe`, `fifo` и Unix-сокеты. В реализации `pipe` вспомогательный Unix-сокет используется только для передачи дескрипторов через `SCM_RIGHTS`. Игровые данные передаются через неименованные каналы.

## Сборка

Необходимы Linux (glibc 2.30 или новее), компилятор с поддержкой C++17, CMake, Make, Bash и Qt 6 Widgets. Для тестирования нужны GoogleTest, Qt 6 Test и Python 3, для форматирования — clang-format.

```bash
make
```

Готовые приложения помещаются в `bin/`. Промежуточные файлы сборки автоматически удаляются скриптом `build.sh`.

Дополнительные команды:

```bash
make format
make clean
```

## Запуск

Запустить хост в первом терминале:

```bash
./bin/host_fifo
```

В других терминалах запустить клиентов, указав PID хоста, отображаемый в его окне:

```bash
./bin/client_fifo 12345
```

Вместо `12345` необходимо подставить фактический PID хоста.

| IPC | Хост | Клиент |
| --- | --- | --- |
| Pipe | `host_pipe` | `client_pipe` |
| FIFO | `host_fifo` | `client_fifo` |
| Socket | `host_sock` | `client_sock` |

Хост и клиенты должны использовать одинаковый механизм IPC. Для начала новой игры после её завершения необходимо перезапустить хост и клиентов.

## Правила игры

Игра начинается после подключения первого клиента. Волк выбирает число W от 1 до 100 вручную за 3 секунды или автоматически. Живой козлёнок случайно выбирает число K от 1 до 100, мёртвый — от 1 до 50.

- Живой козлёнок прячется, если `abs(W - K) <= 70/n`, иначе погибает.
- Мёртвый козлёнок воскресает, если `abs(W - K) <= 20/n`, иначе остаётся мёртвым.

Здесь `n` — количество участников на начало раунда. Новые клиенты вступают со следующего раунда.

Игра заканчивается после двух последовательных завершённых раундов, в которых все участвующие козлята мертвы. Числа участников, их состояния и результаты раундов отображаются в графическом окне.

make test
