# Лабораторная работа № 2. Межпроцессное взаимодействие

**Вариант № 2 (10 баллов).** Тематическая пошаговая игра «Волк и семеро козлят».
Родственная конфигурация «один к одному»: хост порождает одного козлёнка через
`fork`, ведёт игру и показывает прогресс в окне Qt. Козлёнок отправляет хосту
свои броски и получает статус (жив/мертв) каждого раунда.

Реализованы три способа связи (кодовые имена совпадают с требованиями):

| Файл            | Тип взаимодействия            | Исполняемый файл |
|-----------------|-------------------------------|------------------|
| `conn_seg.cpp`  | общая память (`shmget`)       | `host_seg`       |
| `conn_mq.cpp`   | очереди сообщений (`mq_open`) | `host_mq`        |
| `conn_fifo.cpp` | именованные каналы (`mkfifo`) | `host_fifo`      |

Общий интерфейс транспорта — класс `wolf::Connection` (`open/read/write`),
общая логика синхронизации — в `src/connection.cpp`: локальные семафоры
(`sem_init`, pshared) с тайм-аутом 5 с (`sem_timedwait`). При превышении
тайм-аута бросается исключение, связь прерывается, дочерний процесс
останавливается (`SIGKILL` в деструкторе `GameSession::Process`).

## Правила игры (n = 1 козлёнок)

- Волк выбирает число от 1 до 100. Число вводится в поле ввода хоста;
  если за 3 секунды ввод не отправлен, число выбирается случайно.
- Живой козлёнок случайно выбирает число от 1 до 100. Он прячется, если
  разница с числом волка не больше 70 (порог 70/n при n = 1). Иначе его
  ловят — он становится мертвым.
- Мёртвый козлёнок случайно выбирает число от 1 до 50. Он воскресает, если
  разница с числом волка не больше 20 (порог 20/n при n = 1).
- Игра заканчивается, если козлёнок остаётся мёртвым по итогам двух раундов
  подряд.
- Логику рассчитывает хост; в каждом раунде в окне выводятся числа волка и
  козлёнка и число спрятавшихся, попавшихся и мёртвых козлят.

## Зависимости

- Linux (нативно или WSL) с поддержкой GUI, компилятор с C++17, CMake ≥ 3.16,
  Qt 5 или Qt 6 (Widgets), pthread, rt.

Установка на Ubuntu/Debian:

```bash
sudo apt update
sudo apt install build-essential cmake qtbase5-dev   # или qt6-base-dev
```

На Fedora: `sudo dnf install gcc-c++ cmake qt5-qtbase-devel`.
Для WSL нужен X-сервер (WSLg в Windows 11 или VcXsrv/Xming), без него Qt-приложение
не откроет окно (проверить логику можно тестами — они GUI не требуют).

## Структура проекта

```
Makefile            прокладка: make / make test / make clean
build.sh            сборка/тесты (оборачивает cmake, чистит временные файлы)
CMakeLists.txt      все *.cpp собираются автоматически (GLOB)
src/host.cpp        main() хоста + окно Qt (Волк)
src/game.hpp/.cpp   правила игры, GameSession: fork + протокол раунда
src/connection.*    интерфейс Connection + семафорная синхронизация (5 с)
src/conn_seg.cpp    транспорт: shmget/shmat
src/conn_mq.cpp     транспорт: mq_open
src/conn_fifo.cpp   транспорт: mkfifo
tests/              юнит-тесты правил игры и транспортов
```

## Сборка

Обычная сборка — все исполняемые файлы `host_*`:

```bash
make            # эквивалентно: bash build.sh build
```

или напрямую:

```bash
bash build.sh
```

Скрипт создаёт временную директорию `.build.XXXXXXXX`, конфигурирует и собирает
проект CMake в Release с `-Wall -Werror`, а по завершении удаляет все
промежуточные файлы cmake (`trap ... EXIT`). В корень проекта складываются
готовые исполняемые файлы:

```
host_seg   host_mq   host_fifo
```

## Запуск

```bash
./host_seg    # или ./host_mq, ./host_fifo — поведение идентичное
```

Проверка типа связи «вживую»: `ls /dev/mqueue/` покажет очереди
`wolf_lab2_mq_<pid>_to_host/to_child` при работе `host_mq`; `ls /tmp/wolf_lab2_fifo_*`
— каналы `host_fifo`. После закрытия хоста они удаляются.

## Тесты

make test       # эквивалентно: bash build.sh test
