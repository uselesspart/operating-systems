# Лабораторная работа 1. Демон Dir cleaner (вариант 14)

Демон периодически, через заданный интервал, проверяет папки из конфигурационного файла.
Если в папке `folder` отсутствует файл `ignfile`, её содержимое удаляется (файлы и подпапки,
сама папка остаётся). Если файл `ignfile` есть, демон ничего не делает.
Запуск, ошибки, перечитывание конфига, очистки и завершение работы записываются в syslog
(`openlog`/`syslog`/`closelog`). Только Linux: используются `fork`, `/proc`, `sigtimedwait`.

## Сборка

```bash
./build.sh            # результат: ./daemon, промежуточные файлы удаляются
```

## Тесты

```bash
./run_tests.sh                 # все тесты
./run_tests.sh -L unit         # только unit-тесты
./run_tests.sh -L component    # только компонентные
./run_tests.sh -R Sighup       # по имени
```

| Каталог | Что проверяет |
|---|---|
| `tests/ut/` | классы по отдельности: разбор конфига, очистка папки, pid-файл и `/proc`, синглтон демона |
| `tests/ct/` | демонизация, действие над папками, сигналы, pid-файл, сообщения в syslog |

Компонентные тесты подменяют `/dev/log` своим сокетом и читают, что демон пишет в журнал.

## Конфигурация

Файл `daemon.conf` в рабочей папке (или путь первым аргументом):

```
interval 20
/tmp/test_a keep.txt
relative/dir .ignore      # относительно папки, где лежит конфиг
```

- `interval N` — период между проверками в секундах;
- `folder ignfile` — произвольное число строк. `folder` — папка (абсолютная или относительная
  к папке конфига), `ignfile` — имя файла-«защиты» внутри неё (или абсолютный путь);

Абсолютный путь к конфигу запоминается при запуске (до смены рабочей директории на `/`),
поэтому перечитывание по `SIGHUP` работает независимо от того, откуда был запущен демон.

Быстрая проверка с примером конфига: `./demo.sh` — скрипт сам создаёт папки `/tmp/test_a` и
`/tmp/test_b` с тестовыми файлами, запускает демон и показывает, что осталось в папках.

Демон работает в Linux. На Mac собирайте и запускайте его внутри контейнера
(Docker Desktop должен быть запущен):

```bash
docker run -it --rm -v "$PWD":/app -w /app ubuntu:24.04 bash
apt-get update && apt-get install -y g++ make cmake libgtest-dev
./build.sh && ./demo.sh
# Чтобы запускать тесты из такого контейнера, установите зависимости тестов и выполните `./run_tests.sh`:
apt-get update && apt-get install -y g++ make cmake libgtest-dev
./run_tests.sh
```

## Запуск и управление

```bash
./daemon                          
kill -HUP  $(cat /tmp/dirclean_daemon.pid)   # перечитать конфиг
kill -TERM $(cat /tmp/dirclean_daemon.pid)   # завершить
```

Просмотр журнала:

```bash
journalctl -t dirclean_daemon -f       # journald
grep dirclean_daemon /var/log/syslog   # если используется rsyslog
```

Повторный запуск находит старый экземпляр по pid-файлу `/tmp/dirclean_daemon.pid`, проверяет
его наличие через `/proc/<pid>`, отправляет ему `SIGTERM`, дожидается завершения (до 5 секунд)
и после демонизации записывает свой pid. Путь к pid-файлу можно переопределить переменной
окружения `DIRCLEAN_PID_FILE` (её используют тесты).

## Устройство

Класс `Daemon` — синглтон (
доступ через `Daemon::instance()`).

| Модуль | Назначение |
|---|---|
| `src/config` | разбор конфига, приведение относительных путей к абсолютным |
| `src/cleaner` |   проверка `ignfile` и очистка папки |
| `src/pid_manager` | pid-файл, проверка процесса через `/proc`, остановка старого экземпляра |
| `src/daemon` | синглтон демона: `fork`, `setsid`, `chdir("/")`, закрытие дескрипторов, сигналы, главный цикл |
| `src/main.cpp` | точка входа |

Первая проверка выполняется сразу после запуска, затем каждые `interval` секунд.
