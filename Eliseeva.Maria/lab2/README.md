# Межпроцессное взаимодействие в Linux — локальный сетевой чат

**Вариант 18.** Конфигурация: **«Родственные», один ко многим**. Типы взаимодействия: **5, 6, 7**.

Язык: C++17

Сборка: CMake + `build.sh` + `Makefile`.

### Типы взаимодействия 
| № | Тип | TYPE_CODE | Особенности для родственных процессов |
|---|-----|-----------|----------------------------------------|
| 5 | Программные каналы | `pipe` | анонимные каналы, наследуются при fork |
| 6 | Именованные каналы | `fifo` | работа с каналом — в каждом процессе уже после создания дочернего (как у несвязанных); после работы родитель удаляет файл канала |
| 7 | Сокеты | `sock` | `socketpair` |

### Основной сценарий: локальный сетевой чат
Хост и клиенты — участники чата. Хост может сам отправлять личные и общие сообщения, а также передаёт сообщения от других участников в общий чат или лично. Общие сообщения видят все подключённые участники; личные — только отправитель и адресат. Если клиент (не хост) не отправляет сообщений больше минуты, ему отправляется `SIGKILL`. Сообщения появляются в чате в порядке времени отправления.


### Структура проекта
| Файл | Назначение |
|------|-----------|
| `host.cpp` | `main` хоста, окно хоста (Qt), поток на клиента, маршрутизация, контроль неактивности |

| `conn.h` | общий интерфейс класса `Conn` |

| `protocol.h` | формат сообщения (фиксированный, 256 байт) |
| `sem.h` | локальный семафор `sem_init` с `sem_timedwait` (5 с) |
| `log.h` | лог в stderr и файл |
| `CMakeLists.txt`, `build.sh`, `Makefile` | сборка |
| `tests/`, `run_tests.sh` | тесты |
| `Dockerfile` | докер запуск |

### Архитектура
- Хост создаёт канал на клиента (`Conn(id, true)`), делает `fork`, в ребёнке — `exec` бинарника с `--client <id> <описание канала>`. Родитель закрывает клиентские концы.
- Для **каждого клиента** — отдельный поток хоста: `Open()` → ожидание `HELLO` → цикл чтения сообщений.
- **Семафоры (локальные, `sem_init`)**: глобальный семафор защищает таблицу клиентов и порядок сообщений (порядок = порядок захвата, время ставит хост); у каждого клиента свой семафор записи. Все захваты — с тайм-аутом 5 с.
- **Сообщения**: `HELLO`, `CHAT` (общее/личное), `USERS` (список участников), `SYS` (статус). Общие доставляются всем (включая отправителя), личные — адресату и эхом отправителю; хост показывает только те, где он отправитель или адресат.
- **Неактивность**: раз в секунду хост проверяет клиентов; тишина > 60 с → `SIGKILL`, статус в GUI.
- **Тайм-ауты**: запись в канал (5 с), ожидание `HELLO` (5 с), ожидание первого ответа хоста на клиенте (5 с), семафоры (5 с); при превышении связь прерывается, клиент завершает работу. Плановое ожидание сообщений идёт срезами по 0,5 с (чтобы потоки можно было остановить).
- **Статусные сообщения** в GUI: хост/клиент запущен, присоединился, отключился, связь потеряна, убит за неактивность и т. д. Всё дублируется в лог (`chat_host_<тип>.log`, `chat_client<N>_<тип>.log`).
- **Ошибки**: все системные вызовы проверяются, сообщения — в лог/GUI; `SIGPIPE` игнорируется.

## Сборка и запуск в Linux

### Зависимости
Ubuntu/Debian:
```bash
sudo apt update
sudo apt install -y build-essential cmake qt6-base-dev procps
# (вместо qt6-base-dev можно qtbase5-dev)
```
Fedora: `sudo dnf install gcc-c++ cmake qt6-qtbase-devel procps-ng`

### Сборка
```bash
chmod +x build.sh        # один раз
make                     # то же, что ./build.sh
```
`build.sh` собирает проект во временной папке и удаляет её; в папке проекта остаются `host_pipe`, `host_fifo`, `host_sock`. Очистка: `make clean` (или `./build.sh clean`).

### Запуск
```bash
./host_pipe     # или ./host_fifo, ./host_sock
```
В окне хоста: кнопка **«Добавить клиента»** запускает нового клиента (отдельное окно). В каждом окне выберите адресата («Всем» или конкретный участник), введите текст, нажмите Enter.

## 5. Тесты

Запуск (нужны зависимости из раздела 3): `./run_tests.sh` — собирает проект и выполняет всё ниже.

### Модульные тесты (`tests/test_core.cpp`, `tests/test_conn.cpp`, ctest)
`test_conn` линкуется с каждым `conn_*.cpp` — **все три типа проверяются одинаковыми сценариями**:
1. обмен 1000 сообщениями «запрос — ответ»: целостность и порядок;
2. тайм-аут чтения (нет данных → 0 за заданное время);
3. тайм-аут записи (собеседник не читает → `Write` возвращает `false`);
4. штатное завершение собеседника: чтение видит обрыв, запись — ошибку (без `SIGPIPE`);
5. убийство собеседника `SIGKILL`: хост замечает обрыв;
6. **один ко многим**: 8 клиентов, поток на клиента, по 200 сообщений в строгом порядке;
7. для fifo: файлы каналов удаляются хостом;
8. некорректное описание канала → исключение.

`test_core`: формат и обрезка сообщений (UTF-8), семафор с тайм-аутом, `read_all`/`write_all` с тайм-аутами (частичные сообщения, EOF, переполнение канала).

### Интеграционные тесты (`tests/smoke_test.sh`, для каждого `host_*`)
Запускается настоящий хост (Qt, `QT_QPA_PLATFORM=offscreen`), который сам порождает клиентов; результат проверяется по логам:
- **Сценарий A** (3 клиента): все присоединились; общие сообщения видят все и хост; личное 1→2 видят только 1 и 2 (не клиент 3 и не хост), личное 3→2 видят только 3 и 2; файлы fifo удалены; после выхода хоста клиентов не осталось.
- **Сценарий Б** (неактивность): молчащие клиенты убиваются `SIGKILL`, хост сообщает об отключении.

Для автотестов хост и клиент понимают переменные окружения (в обычной работе не нужны): `CHAT_AUTOSPAWN`, `CHAT_EXIT_AFTER_MS`, `CHAT_IDLE_MS` (порог неактивности вместо 60000 мс), `CHAT_AUTOSAY`, `CHAT_AUTOSAY_TO`.
