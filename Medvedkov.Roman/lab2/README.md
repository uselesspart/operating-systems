# Лабораторная работа №2 — локальный чат

Медведьков Роман. Вариант **13**: сценарий 2, родственные процессы,
один к одному, IPC **mq / fifo / sock**.

Хост создаёт ровно одного клиента через `fork()`. После запуска открываются
два окна Qt: хост и клиент. Каждый участник может отправить общее сообщение
или личное собеседнику. Отдельного исполняемого клиента и `client.cpp` нет:
в родственной конфигурации обе ветви выполнения начинаются в `src/host.cpp`.

## Сборка

Требуются Linux, C++17, Make, CMake 3.16+, Qt 5 Widgets и Qt Test.
Для Ubuntu 22.04:

```sh
sudo apt update
sudo apt install build-essential cmake qtbase5-dev python3
cd Medvedkov.Roman/lab2
make
```

Результат — `host_mq`, `host_fifo`, `host_sock` в корне `lab2`.
Можно также вызвать `bash build.sh`. `make` запускает этот скрипт, который
вызывает CMake, а затем компилятор с `-Wall -Wextra -Werror`, оптимизацией
Release и `_FORTIFY_SOURCE=2`.

Все временные файлы CMake, объектные файлы и библиотеки создаются вне проекта
в каталоге `mktemp` и удаляются через `trap` при успехе и ошибке сборки.
В проект копируются только готовые исполняемые файлы.

```sh
make clean
```

CMake автоматически находит обычные `.cpp` и `.c` в `src/` (включая
подкаталоги) и корне проекта и компилирует их в объектные файлы общей библиотеки.
Каждый `conn_TYPE.cpp` или `conn_TYPE.c` автоматически создаёт `host_TYPE`.
Изменять `CMakeLists.txt` при добавлении исходника или транспорта не нужно.
Новый транспорт должен реализовать тот же интерфейс и фабрику, что существующие.
Тестовые `.cpp` находятся отдельно в `tests/` и имеют собственные точки входа.

## Запуск

В графической Linux-сессии запустите один из вариантов:

```sh
./host_mq
# либо ./host_fifo
# либо ./host_sock
```

У каждого участника есть история сообщений, статус подключения, выбор
получателя, поле ввода и кнопка отправки. Enter также отправляет сообщение.
Общие сообщения отображаются обычным цветом, личные — фиолетовым.
В истории видны порядковый номер, время отправки, отправитель и адресат.

В конфигурации с двумя участниками личное сообщение собеседнику видят оба:
один является отправителем, другой — адресатом. Тип сообщения всё равно
сохраняется в протоколе и явно отмечается в истории.

Текст — до 768 байт UTF-8. Счётчик показывает именно байты, поэтому для
кириллицы допустимое количество символов меньше. Пустые сообщения и строки
из одних пробелов не отправляются. HTML в тексте отображается буквально.

Хост не завершается из-за бездействия. Если клиент не отправляет сообщений
**больше 60 секунд**, хост посылает ему **SIGKILL**, получает статус через
`waitpid` и показывает причину отключения. Получение сообщений от хоста
не сбрасывает таймер клиента: учитываются именно отправки клиента.
Окно хоста остаётся открытым, чтобы можно было прочитать статус и историю;
редактор после отключения блокируется. Повторное подключение не предусмотрено.

Закрытие хоста завершает клиента и освобождает IPC-ресурсы. Закрытие клиента
отображается у хоста как отключение. `SIGINT` и `SIGTERM` корректно закрывают
окно. При исчезновении хоста клиент останавливается; дополнительно используется
`PR_SET_PDEATHSIG`. Ошибки выводятся в stderr и в статус интерфейса.

## Классы и обмен

| Класс | Ответственность |
|---|---|
| `Message` | Формат пакета, проверка полей, текст и адресация |
| `SharedSession` | Локальные семафоры, глобальный номер отправки, время активности |
| `Connection` | Единый интерфейс `Open`, `Read`, `Write` и контроль тайм-аутов |
| `MessageQueueConnection` | Очереди POSIX, реализация в `src/conn_mq.cpp` |
| `FifoConnection` | Два направленных FIFO, реализация в `src/conn_fifo.cpp` |
| `SocketConnection` | `socketpair(AF_UNIX, SOCK_SEQPACKET)`, `src/conn_sock.cpp` |
| `MessageOrder` | Упорядочение запросов, пришедших хосту с разной задержкой |
| `ChatSession` | Маршрутизация, подтверждение отправок, отключение, контроль клиента |
| `ChatWindow` | Виджеты Qt, ввод, история и статусы |
| `SessionResources` | Уникальные имена и приватный каталог сеанса |
| `ChildProcess`, `FileDescriptor` | Владение процессом и дескрипторами, освобождение ресурсов |

`SharedSession` создаёт анонимную общую память до `fork` и размещает в ней
локальные семафоры `sem_init(..., pshared=1, ...)`. Текст сообщений в общей
памяти не хранится: каждый пакет передаётся выбранным IPC-механизмом.

Для MQ и FIFO создание и открытие выполняются **после `fork`**. Хост создаёт
ресурсы, потомок открывает свою сторону; готовность координируют локальные
семафоры. Знакомства через сигналы нет. Для родственных процессов в сокетном
варианте используется `socketpair` до `fork`; каждый процесс закрывает чужой конец.

У каждого направления передачи есть семафоры свободного и занятого слота.
Отправитель не перезаписывает непрочитанный пакет. FIFO-пакет меньше `PIPE_BUF`,
а чтение дополнительно умеет собирать кадр частями. Qt-таймер обслуживает обмен
без отдельного потока; ожидание пользовательского ввода не блокирует GUI.

Ожидание создания канала и блокирующие ожидания семафоров ограничены 5 секундами.
Занятый слот проверяется неблокирующим `sem_trywait`; срок отправки, чтения
пакета и ответа хоста также ограничен 5 секундами. При тайм-ауте соединение
закрывается, клиент останавливается. Отсутствие новых сообщений при свободном
канале считается обычным ожиданием ввода пользователя, поэтому само по себе
не вызывает отключение через 5 секунд.

В момент отправки общий семафор выдаёт номер и временную метку. Метки строго
возрастают даже при коррекции системных часов. Хост объединяет собственные
запросы с клиентскими и ждёт отсутствующий более ранний номер не более 5 секунд.
Затем рассылает готовые записи обоим участникам. Поэтому более поздняя отправка
не обгоняет более раннюю из-за задержки IPC; собственное сообщение клиента
появляется в истории после ответа хоста, без повторного локального добавления.

Имена MQ и FIFO уникальны для каждого запуска. FIFO размещены в приватном
каталоге `/tmp/roman-chat-XXXXXX`, права — 0600. Хост удаляет созданные им
очереди и FIFO после остановки потомка. Семафоры уничтожаются родителем после
получения статуса дочернего процесса.

## Тесты

Сборка и основные автоматические проверки:

```sh
make test
```

Полная проверка, включая автоматическое обнаружение исходников и настоящий
минутный таймер для всех трёх транспортов:

```sh
bash tests/run.sh
```

Проверяются:

- протокол, границы длины, UTF-8, адресация и повреждённые пакеты;
- номера и метки времени, разделяемые через `fork`, и работа семафоров;
- двусторонняя передача 40 пакетов каждым транспортом и максимальная длина;
- обратное давление, отсутствие клиента и тайм-аут 5 секунд;
- задержанный ранний запрос, одинаковый порядок у обеих сторон и ответ хоста;
- настоящие Qt-виджеты в обоих процессах: кнопка, Enter, личные сообщения,
  буквальный HTML, счётчик байтов, история и отключение;
- автоматическая компиляция добавленных `.cpp`/`.c`, создание `host_probe`,
  наличие обязательных флагов и очистка CMake-файлов при ошибке и успехе;
- реальные 60 секунд неактивности, SIGKILL клиента, отсутствие зомби,
  сохранение работающего хоста и удаление IPC-ресурсов при закрытии.

GUI-тесты используют платформу Qt `offscreen`, поэтому графический сервер
для `make test` не требуется. `tests/runtime_checks.py` также запускает
готовые программы с `QT_QPA_PLATFORM=offscreen` и проверяет процессы через `/proc`.

Для повторения в контейнере из каталога `lab2`:

```sh
docker run --rm --init -v "$PWD:/src:ro" ubuntu:22.04 bash -lc '
  set -e
  apt-get update
  apt-get install -y build-essential cmake qtbase5-dev python3
  cp -a /src /tmp/lab2
  cd /tmp/lab2
  g++ --version
  bash tests/run.sh
'
```

Исходники подключаются только для чтения, сборка и тесты выполняются на копии
внутри контейнера. Для обычного интерактивного использования нужен графический
сеанс с Qt Widgets.
