# Лабораторная работа №1: напоминалка

**Автор:** Медведьков Роман. 5030102/30201 **Вариант:** 19 Напоминалка.

Программа на C++17 работает в фоне и проверяет расписание каждые 10 секунд.
Напоминание появляется в отдельном окне терминала. События добавляются скриптом
`add_event.sh`; повторы `-h`, `-d`, `-w` означают час, сутки и неделю.

## Сборка и первый запуск

Нужны Linux с `/proc`, `g++` с поддержкой C++17, Bash, `flock` (util-linux),
стандартные утилиты GNU и графическая сессия с `xterm`.
На Debian/Ubuntu зависимости устанавливаются командой:

```sh
sudo apt install g++ xterm util-linux
cd Medvedkov.Roman/lab1
bash build.sh
./reminder --check reminder.conf
./reminder
bash add_event.sh 2026-10-26 09:00 Сдать лабораторную по ОС
bash add_event.sh 2026-10-26 10:00 -h Сделать перерыв
bash add_event.sh 2026-10-26 08:30 -d Проверить расписание
bash add_event.sh 2026-10-26 12:00 -w Еженедельная встреча
```

Подставьте будущие дату и время. Запускайте из терминала графической сессии
под своим пользователем: демон наследует `DISPLAY`, `WAYLAND_DISPLAY`,
`XAUTHORITY` и окружение D-Bus. Для чистого SSH без X forwarding окна недоступны.

`build.sh` вызывает `g++ -std=c++17 -Wall -Wextra -Werror`, собирает один
исполняемый файл `reminder`. Временный каталог сборки удаляется через `trap`
как при успехе, так и при ошибке. Сторонние библиотеки не нужны.

## Конфигурация

Файл по умолчанию — `reminder.conf` в текущей папке запуска. Можно указать
другой файл: `./reminder /полный/путь/расписание.conf`. Абсолютный путь
вычисляется до демонизации и сохраняется для последующих перечитываний.

```text
# Пустые строки и строки комментариев разрешены.
interval 10
terminal xterm
add_event 2026-10-26 09:00 Разовое напоминание
add_event 2026-10-26 10:00:30 -h Повтор каждый час
```

Дата имеет формат `YYYY-MM-DD`, время — `HH:MM` или `HH:MM:SS`, часовой пояс
локальный, унаследованный от запускающей сессии. Несуществующие даты и время
(включая пропущенный при переводе часов час) отвергаются. Неоднозначный час
осенью интерпретируется `mktime` согласно системному часовому поясу.
Периоды повторов фиксированы: 3600, 86400 и 604800 секунд; при переходе на
летнее/зимнее время местный час суточного повтора может измениться.

`interval` задаётся в секундах, диапазон 1–86400, значение по умолчанию 10.
Обычная задержка показа — до одного интервала проверки. Новое событие из
прошлого допускается только в пределах одного интервала; более старое разовое
напоминание пропускается. Повторяемое переносится к ближайшему актуальному
срабатыванию с сохранением привязки к исходному времени. После сна компьютера
накопленные повторы объединяются в одно уведомление, затем расписание
продолжается с ближайшего будущего срока.

`terminal` — имя программы из `PATH` или абсолютный путь без пробелов.
Терминал должен поддерживать `-e program argument...`: подходят `xterm` и
обычный Debian/Ubuntu `x-terminal-emulator`. Аргументы в значении `terminal`
не предусмотрены. Текст передаётся отдельным аргументом в фиксированную
shell-программу и печатается через `printf '%s'`: кавычки, `$()` и `;` из текста
не исполняются. Окно остаётся открытым до нажатия Enter.

Строка события занимает одну строку; текст не должен начинаться с `-`.
Одинаковые события (время, период, текст) объединяются в одно.

## Скрипт и сигналы

`add_event.sh date time [flag] text` проверяет событие тем же C++-парсером,
добавляет строку в конфиг под `flock` и отправляет работающему демону `SIGHUP`.
Если демон выключен, запись сохраняется для следующего запуска.
Проверка `/proc/<pid>/exe` и владельца не позволяет отправить сигнал чужой
программе из-за устаревшего PID. Для другого конфига:

```sh
REMINDER_CONFIG=/полный/путь/расписание.conf bash add_event.sh 2026-10-26 18:00 Текст
kill -HUP "$(cat reminder.conf.pid)"
kill -TERM "$(cat reminder.conf.pid)"
journalctl -t roman-reminder -f
```

`SIGHUP` перечитывает конфиг целиком. При ошибке демон пишет причину в журнал и
продолжает по прежнему расписанию. Уже показанные события не повторяются при
перечитывании, даже если их временно удалить из конфига и вернуть. Эта история
хранится в памяти процесса: перезапуск её очищает. Одновременное ручное
редактирование и запись скриптом следует исключить; блокировка координирует
именно запуски скрипта между собой.

`SIGTERM` и `SIGINT` записывают сообщение о завершении, очищают PID-файл и
завершают демон. Ранее открытые окна терминала остаются у пользователя.
В системах без доступного `journalctl` сообщения ищите в настроенном системном
журнале (`/var/log/syslog` и т. п.). Используются `openlog`, `syslog`, `closelog`,
идентификатор `roman-reminder`, facility `LOG_DAEMON`.

## Демонизация и единственный экземпляр

`Daemon` — синглтон с приватным конструктором и запрещённым копированием.
Последовательность запуска: чтение настроек, блокировка запуска, проверка
старого PID через `/proc`, `SIGTERM` предыдущему экземпляру, ожидание освобождения
PID-блокировки (до 5 секунд), `fork`, `setsid`, второй `fork`, `chdir("/")`,
закрытие унаследованных дескрипторов, перенаправление 0/1/2 в `/dev/null`.
Новый PID записывается после демонизации. Родитель ждёт подтверждения запуска
по pipe, поэтому успешный код возврата означает, что демон уже создал расписание.

PID-файл по умолчанию лежит рядом с конфигом и называется `<config>.pid`.
Для одного конфига используйте один и тот же PID-файл. Явное указание:

```sh
./reminder /path/events.conf /path/service.pid
REMINDER_CONFIG=/path/events.conf REMINDER_PIDFILE=/path/service.pid \
    bash add_event.sh 2026-10-26 18:00 Текст
```

Файл `.pid.launch` блокирует конкурирующие запуски; PID-файл держит блокировку
на всё время работы демона. Эти файлы должны находиться в принадлежащей
пользователю папке. Символические ссылки и файлы другого владельца отвергаются.
Чужой живой процесс из PID-файла останавливать запрещено: запуск завершится
ошибкой. Отсутствующий процесс и обычная мусорная запись восстанавливаются.
После остановки PID-файл остаётся пустым, `.launch` тоже остаётся на диске:
сохранение inode исключает гонку блокировок при удалении файла.

Сигналы читаются через Linux `signalfd` и `poll` в основном цикле. Функции
журналирования и чтения файлов не вызываются из обработчика сигнала.
Завершившиеся процессы терминалов убираются `waitpid(..., WNOHANG)` по `SIGCHLD`.
Ошибки `fork`, `exec` и ненулевое завершение терминала записываются в журнал.
Неудачный показ автоматически не повторяется; проверьте терминал перед запуском.

## Проверки

Для сборки и запуска тестов в Linux:

```sh
bash tests/run.sh
```

Тесты собирают программу с обязательными флагами и проверяют:

- разбор дат, високосный год, ошибочные время/флаги/пустой текст;
- все три периода, одноразовое событие, дубликаты, будущие и просроченные события;
- сохранение истории при перечитывании и отсутствие шквала повторов после паузы;
- чтение конфига, ошибочный интервал;
- настоящий фоновый процесс, рабочую папку `/`, стандартные дескрипторы;
- добавление скриптом, сигнал SIGHUP и буквальную передачу shell-символов;
- сохранение расписания после ошибки перечитывания;
- замену предыдущего процесса, устаревший PID, SIGTERM и очистку PID-файла.

Интеграционные тесты используют временные конфиг/PID-файл и подставной терминал,
поэтому графический сервер не нужен. Настоящее окно и записи системного журнала
проверяются отдельно вручную: добавьте событие на минуту вперёд, дождитесь окна,
сравните текст, отправьте `SIGTERM` и проверьте `journalctl -t roman-reminder`.

## Файлы и объяснение для защиты

Каждый основной класс имеет одноимённые `.hpp` в `include/` и `.cpp` в `src/`.

| Класс | Ответственность |
|---|---|
| `ReminderEvent` | Одно событие: дата, период, текст; разбор строки события |
| `Configuration` | Данные настроек: интервал, терминал, список событий |
| `ConfigLoader` | Чтение файла и проверка настроек до их применения |
| `ReminderSchedule` | Очередь ближайших событий, расчёт повторов и история показов |
| `PidFile` | PID-файл, проверка старого процесса, блокировки и запись нового PID |
| `TerminalNotifier` | Запуск окна терминала и получение статусов дочерних процессов |
| `Daemon` | Синглтон: демонизация, основной цикл, сигналы и смена конфигурации |
| `FileDescriptor` | Автоматическое закрытие принадлежащего объекту дескриптора |

`Daemon` хранит `Configuration` и `ReminderSchedule` как свои поля.
`ConfigLoader::load()` возвращает проверенную конфигурацию, а
`ReminderSchedule::reload()` применяет её к расписанию.
`ReminderSchedule::takeDue()` возвращает события, которые пора показать;
`TerminalNotifier::show()` запускает для них окна.

`Daemon::run()` отвечает за запуск, `prepareProcess()` — за отсоединение от
терминала, `runLoop()` — за цикл ожидания, `reloadConfiguration()` — за SIGHUP.
Работа с PID-файлом и запуск терминалов вынесены из класса демона.

`main.cpp` проверяет аргументы и вычисляет абсолютные пути. `build.sh` собирает
программу, `add_event.sh` добавляет события. `tests/ReminderTests.cpp` проверяет
переносимую часть, а `tests/run.sh` дополнительно проверяет настоящий Linux-процесс.

`fork` создаёт потомка с копией адресного пространства, `setsid` отсоединяет
его от управляющего терминала. Второй `fork` оставляет демон вне роли лидера
сессии. `exec` в дочернем процессе заменяет его программу терминалом, а
`waitpid` получает статус завершения и освобождает запись процесса-зомби.
Очередь с приоритетом хранит ближайшее срабатывание каждого напоминания:
проверка не требует пересчитывать все будущие события при каждом пробуждении.
